# 列表页：表格页的视图区（步骤 2 前读，步骤 4 过检查清单）

本文用于画表格页的视图区：结构由产品定死（视图页签 → 视图区白卡：工具栏 → 当前视图 → 合计行／分页器），要定的只有视图形态、工具栏露哪些、列与行。视图名称由用户配，不代表新引擎；页面里的表格列表组件走 [workbench.md](workbench.md) 或 [item-detail.md](item-detail.md)。用法：按第 1 节选视图与组件，第 2 节定布局。

## 1. 组件选取规则

### 视图引擎

产品的视图七种：网格、看板、卡片、日历、甘特、任务、透视表。同一页面只画当前视图一种引擎。网格视图占绝大多数，甘特、看板、卡片少见，日历与任务视图几乎不用。

| 业务要看什么 | 视图 | 判据 |
| --- | --- | --- |
| 逐条核对、批量处理 | 网格视图（默认） | 没有特别理由就用网格；字段多、要看合计时必用 |
| 按状态推进（待处理→处理中→完成） | 看板视图 | 分组字段必须是一个单选选项字段；列 3～5 个，每列卡片数不均匀 |
| 按日期排布（排班、巡检、拜访） | 日历视图 | 表里有日期字段；无底部合计行 |
| 有起止时间的计划（项目、生产、工期） | 甘特视图 | 需要标题＋开始日期＋结束日期字段，可带进度 |
| 有层级的任务 | 任务视图 | 需要标题／状态／所属任务／负责人／截止日期五个角色字段 |
| 有封面图的主数据（商品、房源、人员） | 卡片视图 | 每张卡一张图＋标题＋2～3 字段；未实测采集，画前告知 |
| 多维汇总 | 透视表视图 | 行分组＋列分组＋统计值；未实测采集 |

### 工具栏

可选工具八个：字段、分组、筛选、排序、冻结、行高、导入、导出；右侧固定搜索框＋新建主按钮。露 4～6 个，已配置的工具显示条数（"筛选 1"）。

### 表格内的单元格组件

| 字段类型 | 显示为 |
| --- | --- |
| 单选／多选选项 | 彩色标签（状态按红绿灯语义着色）／多值标签 |
| 成员 | 头像＋姓名 |
| 有快捷按钮的表 | 行内操作按钮（打印、出库、审核），放最后一列 |
| 数值、金额 | 右对齐，金额带千分位与零头 |
| 关联数据 | 关联记录标题 |

### 附属件

- 分组行：分组视图才有，每组一行，组内数据照常。
- 合计行：有数值列且配了统计时出现，tfoot 与列对齐，最左格记录数，配了统计的列写"求和 26,587"，其余留空。
- 分页器：数据超一页时出现在合计行下方。
- 视图页签：2～6 个，当前视图高亮。

## 2. 布局原则

### 结构（固定，不可增减层级）

视图页签 → `.view-box` 白卡（白底、圆角 6、1px 黑 8% 边、四周留缝 12～16）→ 工具栏（48 高）→ 视图 → 合计行／分页器。工具栏与视图必须同在白卡内，缺这层会出现工具栏透灰底的色带。列表页的视图区白卡浮灰底是产品强特征，不参与"白底描边／浅底白卡"切换。

### 网格视图

- 首列勾选＋行号合并 95 宽；表头 32 高；数据行 35 高（矮档；中档、高档 72 换行），默认列宽 140。
- 列数 6～13，默认 10 左右；超过画布宽度的列被裁掉是产品原样，右侧出横向滚动条。
- 列顺序：标题或编号列在最前（冻结），状态、金额、负责人这类决策列靠前，创建时间等系统字段靠后，操作列最后。
- 冻结列 ≤6。
- 行数 6～14。少于 6 行撑不满视图；超过 14 行会被 check.py 的 `scale-limit` 提示，确要长表就在验收表第 8 条写明理由，多出的行由窗口自然裁断。

### 看板视图

- 列 254 宽透明底、列间距 24；列头 50 高＝彩底胶囊分组名＋数量；卡片白底圆角 6、内距 12，字段竖排。列数 3～5，每列卡片 2～6 张，各列数量不均。

### 日历／甘特／任务

- 日历：星期表头 25 高，日期格 86 高，今天主色实底；无合计行。
- 甘特：左侧字段表＋右侧时间轴，任务条带进度与依赖线。
- 任务：字段表头＋分组行＋层级任务记录，底部记录数。

### 营销浮层

列表页配图常带浮层（默认右探出），内容规则见 [../canvas/marketing.md](../canvas/marketing.md)；常放记录详情卡、快捷表单、点击后的下拉或弹窗。

## 3. 色彩

- 状态、类别这类选项字段用彩色标签，颜色按 [visual-four-principles.md](visual-four-principles.md) 的红绿灯语义：红＝异常／驳回，橙＝待处理，绿＝完成；同一列同一语义同一色。
- 视图区白卡、表头浅灰底、行分隔线走 base.css，不另加底色；页面里只有一个填充式主按钮（新建）。

## 4. 数据与文案

- 编号有规则且不连号（WZ-JS-0106、WZ-CY-0412），金额有零头，日期不等距，同一人重复出现，状态分布不均匀。
- 至少一处非理想态：空值"—"、超长截断、驳回红标、置灰按钮。
- 视图名称写业务（"待发货""本周巡检"），不写"视图 1"。
- 工具栏条数与表格内容对得上（写了"筛选 1"，表格就是筛过的）。
- 数据毛边规则见 [anti-sameness.md](anti-sameness.md)。

## 5. 禁止项

- 合计写成堆在左下角的一行文字。
- 工具栏和视图不在同一白卡内。
- 一页画两种视图引擎。
- 视图页签名当成新引擎（"透视"不等于透视表视图）。
- 画未采集的卡片视图、透视表视图而不告知用户。
- 表格只有三两行凑数。
- 列表页混进横幅、单指标、按钮组件（那是自定义页面）。

## 6. 检查清单

逐图回答"通过／改过（改了什么）"。

1. 视图引擎与业务对得上（推进用看板、排期用日历、有起止用甘特，其余网格）。
2. 结构是视图页签 → 白卡（工具栏 → 视图 → 合计／分页），层级不多不少。
3. 工具栏 4～6 个工具，已配置的显示条数。
4. 表格 6～14 行、6～13 列，首列勾选＋行号，操作列在最后。
5. 状态列按红绿灯着色，成员列有头像。
6. 有数值列的表带合计行且与列对齐。
7. 通用项（数据像真的、浮层、对齐）按 [../canvas/verify-export.md](../canvas/verify-export.md) 的十条表。
