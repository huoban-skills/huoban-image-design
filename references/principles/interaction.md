# 交互界面：点了按钮之后的那一屏（步骤 2 前读，步骤 4 过检查清单）

本文用于画快捷按钮、页面按钮点开后系统接着让人做的那一步：勾一批记录、批量改几格、确认一句、填几个参数、扫码、打印、看一个嵌进来的网页。它们是自动化「页面交互」节点各自打开的界面，压在发起它的页面上。只有电脑端的形态，手机端点开这些节点的样子未采集，需求里出现时先告知用户。底图（列表页、详情页、工作台）的内容仍按对应页面篇；宏怎么写看 `expand.py --doc 宏名`，尺寸看 assets/c2-table-form.html「交互界面」一节的 `data-measured`。

## 1. 布局原则

- 一张图一步：`<hb-page kind="list|detail|workbench">` 体内照常写底图，再放一个交互界面宏。先选再填这种两步流程拆成两张图。
- 按画布放：营销画布（报告配图、方案演示稿）把交互界面宏写进 `<hb-float>`，底图保持完整清晰、不加遮罩，读者先看清是哪个页面、点的哪个按钮；产品设计类（`canvas="product"`）写在页面顶层最后，像真实产品一样加遮罩盖在底图上。营销画布写在顶层会报错。
- 底图用按钮所在的那个页面：行内按钮在列表页，记录功能区的按钮在详情页，按钮组件在工作台。被点的那个按钮要露在浮层外面；底图是列表页时，勾选的行、讲点里的操作列放在前几行。
- 浮层的宽、位置、倾斜按 [../canvas/marketing.md](../canvas/marketing.md) 第 3 节：大弹窗和表单写 `w`（底图是列表页时可到 960），确认弹窗、参数填写页、扫码器、嵌入的网页宽度是实测固定的，不写 `w`。
- 产品设计类的窗口高度：数据选择页、数据批量增删改页面、打印数据、嵌入的网页占掉大半个窗口，窗口固定撑到 900 高；确认弹窗、参数填写页、扫码器是居中的小窗，窗口高度仍由底图定。

## 2. 组件选取规则

| 自动化节点 | 讲什么时用 | 画法 |
| --- | --- | --- |
| 打开数据选择页（单选／多选） | 从一批记录里勾出要处理的那条或那几条：选应收明细核销、选报价单关联 | `hb-pick`；单选写 `single`：同一个界面，没有「只看已选」、表头勾选框和底栏，点一行就选定 |
| 打开数据批量增删改页面 | 一次改一批、补一批：派工确认、填本次核销金额 | `hb-batch`；节点只许改不许新增时写 `noadd` |
| 打开确认弹窗 | 系统停下来问一句，点哪个按钮走哪条分支；改了不能撤的事先让人看清要改什么 | `hb-confirm`；要提醒后果时加 `icon="warning"` 和一段提示内容 |
| 打开参数填写页 | 执行前先问几个值，值不落在任何表上：账期起止、新交期、原因 | `hb-params`；后面还接一步时主按钮写「下一步」 |
| 打开扫码器 | 电脑上接扫码枪，或手输后回车 | `hb-scanbox`；手机上扫码用 `hb-scan` |
| 打印数据 | 按模板打出单据 | `hb-print` |
| 查看嵌入的网页 | 不离开系统看外部页面：客户位置地图、物流轨迹、BI 报表 | `hb-embed`；网页区放客户给的截图，没有截图用地图、图表宏代替，不手画第三方网站 |
| 打开数据创建页／打开数据编辑页 | 点按钮带出一张预填好的单 | `hb-form`（字段区、子表的写法见 [form.md](form.md)）；节点配了提示时写 `tip`，标题栏下出一条提示条 |
| 打开数据查看页 | 办完跳到结果记录 | 详情页（[item-detail.md](item-detail.md)） |
| 跳转到、复制内容到剪贴板、跳转浏览器下载 | — | 没有自己的界面，不画；要讲就画它到达的那个页面 |

选哪一个看这一步人要做的事，不看按钮叫什么：要人挑记录用数据选择页，要人改记录上的字段用批量增删改，要人给一个不存档的值用参数填写页，只要人点头用确认弹窗。

## 3. 数据与文案

| 界面 | 数量 |
| --- | --- |
| 数据选择页 | 5～12 行、5～7 列；多选标 1～3 行，单选标 1 行，标的是这一步真会选的 |
| 数据批量增删改页面 | 3～10 行、5～7 列；必填列标星 |
| 确认弹窗 | 标题 28 字以内；提示内容 60 字以内，可不写；按钮 1～3 个 |
| 参数填写页 | 1～6 个参数 |
| 打印数据 | 标题＋两栏字段 3～5 行＋一张 2～5 行的表＋1～3 段正文 |

- 标题用节点上会配的那种说法：数据选择页和批量增删改写成一句指令（「请选择你要核销的应收明细」「请确认本次核销金额」），参数填写页写要填的东西（「选择账期」）。
- 确认弹窗的按钮名写点了之后发生什么（「确认修改」「跳转订单」），不写「按钮一」；提示内容写清哪条记录、从什么改成什么。
- 弹窗里的单号、客户、金额和底图上被点的那一行对得上。
- 数据选择页里的记录要有该选和不该选的差别（已收完的、别的客户的），读者才看得出为什么勾这几条。
- 打印数据纸上是客户的单据模板，抬头、字段名照客户的叫法；公司名、税号用虚构值。
- 值的写法按字段类型，带颜色的只有选项字段，见 [component-guide.md](component-guide.md)「字段按类型写」。

## 4. 禁止项

- 营销画布里给交互界面加遮罩、盖住整张底图。
- 确认弹窗加关闭叉，或把提示内容写成长段落。
- 给跳转、复制、下载这类没有界面的节点编一个提示框。
- 嵌入的网页里手画高德、百度这类第三方网站的界面。

## 5. 检查清单

逐图回答"通过／改过（改了什么）"。

1. 这张图只讲一步；营销画布里交互界面在浮层里，底图完整清晰。
2. 节点和界面对得上第 2 节的表，没有给无界面的节点画东西。
3. 底图是按钮所在的页面，被点的按钮露在浮层外面。
4. 行数、参数个数、按钮个数在第 3 节的范围内；数据选择页多选标了 1～3 行、单选标了 1 行。
5. 弹窗里的记录和底图被点的那一行是同一件事，单号、客户、金额对得上。
6. 标题和按钮名说的是业务动作。
7. 通用项（数据像真的、对齐）按 [../canvas/verify-export.md](../canvas/verify-export.md) 的十条表。
