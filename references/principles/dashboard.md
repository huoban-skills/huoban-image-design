# 数据看板

本文用于画数据看板。看板让人看出问题、原因和下一步，按"发生了什么 → 为什么 → 该怎么办"讲一段数据故事。有按钮组、待办的是工作台，走 [workbench.md](workbench.md)。用法：先按第 1 节选版式，再按第 2 节配组件，第 3 节定色彩；大屏另见 [screen.md](screen.md)。

## 1. 布局原则

### 版式

从第二行起从上往下判，命中第一条就用，都不命中用第一行的默认版式。同一批看板不重复用一种版式。第二张命中同一版式时，换成表里排在它后面、适用条件也说得通的那一行；都说不通就保留版式，把图表行 16+8 换成 12+12。

| 版式 | 适用 | 结构（从上到下） |
| --- | --- | --- |
| 层叠式 | 一条主线讲三问，指标 4～6 个、图 2～3 张 | 横幅 → 筛选 → 单指标行 → 图表行（16+8 或 12+12）→ 明细 24 |
| 左栏导览式 | 筛选项 4 个以上 | 横幅 → 左 6 栏竖叠筛选组件 3～4 个＋分类汇总通高 ＋ 右 18 栏（单指标 6×3 → 图 9+9 → 明细 18） |
| 宫格式 | 几条平行业务线各看各的，结果指标之间没有主次 | 横幅 → 单指标行 → 8+8+8 或 12+12 同权重图两行 → 明细 24 |
| 页签分段式 | 内容按阶段或业务能分成 3～5 段，每段各有图和表 | 横幅 → 单指标行 → 标签页 24 通栏，页签内自成小看板：筛选 → 图 → 表 |

版式自己定，不问用户，需求单和交付说明里不写版式名。各版式的线框示意见 [assets/layout-gallery.html](../../assets/layout-gallery.html)（浏览器打开）。

### 位置与栅格（24 栅格、组件间距 20；任一版式都守）

栏数和高度是样板配法与上限，按内容和画面自适应，不硬套。横幅写法与形态、页签形态、层次、同排等高、图表卡高度见 [visual-four-principles.md](visual-four-principles.md)。

| 位置 | 规则 |
| --- | --- |
| 整体 | 从上到下对应三问，最重要的数据视图占左上；单指标行落在首屏上半部；一屏放完，超一屏说明指标没拆干净，回需求单的结果／过程／对比三项重拆 |
| 横幅 | 24×5 一行高 |
| 筛选 | 一行放完，2～4 项、各 4～6 栏、高 3，全局生效；只管一段的筛选贴在那段正上方；多页看板的筛选位置一致 |
| 单指标行 | 只放一行：4 个＝6+6+6+6，6 个＝4×6；5 个在产品栅格里不能等分（5+5+5+5+4），示意图可等分但搭建会差一栏。多出来的并成多项统计或改进度条／透视表 |
| 图表行 | 最多三栏，不放四栏：主趋势图放左侧、面积最大（16＋8）；两张同权重 12＋12；环图两张并排或与柱图并排，不单独占一行；官方样板 12＋6＋6（环图＋面积＋双轴，高 20） |
| 明细 | 放最底部，24 通栏，高 13～27；透视表 ≤2 张，两张时 12+12，多了并成一张多维透视；透视表段前放一行筛选 |

## 2. 组件选取规则

按数据故事三问取组件，问题不成立的行不放。组件名用产品中文名，英文 type 在登记表 assets/registry.json 里查。

| 要回答的问题 | 组件 | 必有／可选 | 数量 |
| --- | --- | --- | --- |
| 这页管什么、给谁看 | 富文本「大标题」预设（横幅：页面名＋一句话介绍） | 必有 | 1；官方样板用同一组件做段落标题，看板中段可再出现一次 |
| 看哪个范围（时间、区域、人） | 筛选组件 | 有筛选范围时必有 | 2～4 项；全局筛选或只管一段的局部筛选（官方样板两种都有） |
| 发生了什么：结果指标 | 单指标 | 看板必有；纯图表型看板可无（官方样板「生产数据分析」页直接从图表开始） | 4～6 个；每个带对比（目标、同比、环比、趋势条），没对比的数字不上看板 |
| 主指标怎么变的：趋势 | 折线图 折线／面积图 面积／柱状图 柱状 | 必有 | 1 |
| 为什么：按人／区域／产品分开比 | 柱状图 柱状／条形图 条形／分类汇总／透视表 | 可选 | 1～2 |
| 构成占比 | 饼图（环形态） | 可选 | ≤2 |
| 过程指标：环节达成 | 进度条／多项统计／透视表 | 可选 | 1～3 |
| 我该怎么办：明细与异常 | 表格列表／透视表 | 可选 | ≤2；能靠钻取看到的明细不放；只列异常（超期、低于下限、驳回） |

数量总量：结果指标 4～6 ＋ 图表与表 ≤5，合计 ≤9，一屏放完。

选图表类型或拿不准该用哪个组件时，查 [component-guide.md](component-guide.md)。

## 3. 色彩

- 状态色走红绿灯：成功绿、进行中蓝、警告黄、失败红、未开始灰，全看板一致。
- 系列色不超过三类，主系列用主色、第二系列同色降透明度，第三系列才换色；多系列柱／饼用皮肤里的对比色序列。
- 强调只给一处：异常值、当前期、目标线，其余克制。
- 颜色只通过皮肤 token（`var(--primary)`、`var(--c-red)` 等），选皮肤见 [../skin/routing.md](../skin/routing.md)。

## 4. 数据与文案

- 结果指标必须带参照：目标值、同比／环比、或趋势条，二选一以上。
- 顶行数字的量级要分散（一个 3.4 万、一个 87.5%、一个 12 单），不要四个都是万元。
- 明细表里要有异常态：超期红标、低于下限、驳回，不是清一色正常。
- 筛选项写真实字段名（"月份""仓库""业务员"），不写"筛选一"。
- 横幅介绍学产品口吻，说清这页管什么、给谁看，20 字上下。
- 数据毛边规则见 [anti-sameness.md](anti-sameness.md)。

## 5. 禁止项

- 没有对比值的数字上看板。
- 图表三件套（柱＋折＋饼）每张看板都一样；图表类型跟着故事走。
- 看板里放按钮组、待办、快捷表单、公告。
- 地图画国家或省份轮廓。

## 6. 检查清单

逐图回答"通过／改过（改了什么）"。

1. 从上到下能读出现状 → 问题 → 动作，顺序是横幅、筛选、指标、图表、明细。
2. 单指标 4～6 个、只有一行、每个旁边有对比值或趋势条。
3. 主趋势图在图表行左侧；环图不是孤零零一张。
4. 图表与表合计 ≤5，整页一屏放完，横幅只有一行高。
5. 同一行卡片底边齐。
6. 明细表里有异常态，且只列异常。
7. 没有工作台组件（按钮组、待办、快捷表单）。
8. 地图没有画轮廓。
