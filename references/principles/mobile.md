# 手机端：一屏一件事（步骤 2 前读，步骤 4 过检查清单）

本文用于画手机图：H5、企业微信里打开的伙伴云页面，外部人员用的门户，以及企业微信里收到的通知。手机壳 375 宽，不套产品壳，外层是 `<hb-page kind="mobile">`。宏怎么写看 `expand.py --doc 宏名`，尺寸与层次看 assets/c4-mobile.html 的 `data-measured`，本文只管三件事：画几屏、每屏用哪种界面、放多少内容。手机版的工作台、详情页，内容取舍仍按对应页面篇（[workbench.md](workbench.md)、[item-detail.md](item-detail.md)）。

## 1. 布局原则

### 画几屏

| 要讲什么 | 画法 | 判据 |
| --- | --- | --- |
| 一段动作怎么走 | 流程壳：`hb-screens` 放 2～3 屏，屏间用 `hb-conn` 写一句说明 | 手机图一律这么画，一步一屏 |
| 需求里只提到一个界面 | 仍用流程壳：补上这件事的上一步或下一步，凑成 2 屏 | 入口（消息、列表、工作台）→ 这个界面，或这个界面 → 它的结果态 |
| 超过三步 | 拆成两张图 | 三屏以上手机会缩得看不清字 |

手机图不出单屏：`hb-page kind="mobile"` 的体内一律是 `hb-screens`，不直接放单个 `hb-phone`。需求只提到一个界面时，按上表补出它的上一步或下一步，而不是画成一屏。

例外只有一处：PC 图的浮层里放一个手机单屏（浮层只能放单屏），讲同一件事在手机上怎么办；写法与尺寸见 [../canvas/marketing.md](../canvas/marketing.md)，界面类型照下面的表选，内容控制在 600 高以内。

### 多屏时每一屏是不同类型的界面

流程壳里的 2～3 屏，界面类型不能重复：第一屏是企业微信消息，第二屏就不能还是消息；两屏都是列表页、两屏都是记录页同样不行。流程的看点是从一种界面走到另一种界面，两屏同类读者看不出走了一步（expand 会报错）。

界面类型按下表第一列算。同一条记录的「详情」与「编辑」算两种；「门户里的列表页」与「工作区里的列表页」算同一种。

### 界面类型与业务动作

| 界面类型 | 讲什么动作时用 | 宏（自上而下的顺序） |
| --- | --- | --- |
| 企业微信应用消息 | 系统把待办或结果推给**某个人** | `hb-wxapp` |
| 企业微信群消息 | 系统把通知发进**业务群**，群里的人点开办 | `hb-wxgroup`；卡片消息与 markdown 消息按客户实际用的那种选 |
| 公众号会话 | 客户、外部人员从公众号菜单进来 | 按 c4「公众号图文会话＋底部菜单」模板手写 |
| 工作区首页 | 手机上怎么找到一张表 | `hb-mhome` |
| 列表页 | 现场查数据、按视图看自己那部分 | `hb-vbar` → `hb-ocards` → `hb-mtool` |
| 记录详情页 | 点开一条看全貌 | `hb-rec` → `hb-mtool mode="obar"`；有业务快捷按钮（报修、补录）写在 `btns` 里，排在操作条上方一行，操作条本身固定五项 |
| 扫码页 | 现场对着标签扫一下进系统 | `hb-scan`（企业微信扫一扫，外层 `hb-phone nobar`）|
| 新建／编辑页 | 现场录入、扫码登记 | `hb-rec edit` → `hb-fbar` |
| 流程任务列表 | 我有哪些待办 | `hb-ptasks` |
| 任务办理页 | 核对后通过或驳回 | `hb-rec` → `hb-taskbar` |
| 手机工作台 | 一个角色在手机上的入口 | `hb-wpage`：横幅 → 快捷方式 → 标签页，页签里嵌 `hb-ocards bare` |
| 手机看板 | 老板、主管在手机上看数 | `hb-wpage`：横幅 → 标签页，页签里 `hb-stats`（两个一行）→ 图表宏（一行一个）；不放卡片列表 |
| 门户登录页 | 外部人员怎么进来 | `hb-plogin` |
| 门户页 | 外部人员进来后看到什么 | `hb-ptop` → `hb-pnav` → 上面任一种页面内容；讲导航怎么找再加 `hb-pmenu` |
| 个人中心 | 换手机号、退出登录 | `hb-pme` |

门户页的手机壳写 `nobar`，顶上是门户顶栏和导航条，不出返回顶栏。

### 常用流程组合

| 业务 | 屏序 |
| --- | --- |
| 审批 | 企业微信应用消息 → 任务办理页；或 流程任务列表 → 任务办理页 |
| 群里派单 | 企业微信群消息 → 记录详情页 |
| 现场登记 | 列表页 → 新建／编辑页；或 手机工作台 → 新建／编辑页 |
| 扫码出入库、扫码盘点 | 扫码页 → 记录详情页；或 扫码页 → 新建／编辑页 |
| 外部客户自助 | 门户登录页 → 门户页 →（记录详情页 或 个人中心） |
| 公众号查询 | 公众号会话 → 门户页 |

同一批图里别张张都是「企业微信消息 → 列表 → 详情」，起点在消息、工作台、任务列表之间换着来。

## 2. 组件选取规则

- 列表一律是三槽卡片。手机端没有表格形态，列表页和自定义页面里的明细都用 `hb-ocards`；PC 的网格、看板、透视表放进手机壳 expand 会报错。
- 卡片的三个槽放决策字段：状态、数量或金额、负责人。标题写「谁的什么」，副标题写时间与金额这类补充。
- 配了快捷按钮的表，卡片右下带按钮（「登记取货」「确认收货」），一张卡一个。这张图讲的是某个操作（扫码保养、接单、审批…）而画面是卡片列表时，按钮必须有，按钮名就是那个动作。
- 审批没有独立的流程条：待办看 `hb-ptasks`，办理看 `hb-rec` ＋ `hb-taskbar`，不画 PC 那种时间线。
- 记录页里本节点要填的字段、计算出来的字段用 `!` 高亮，读者一眼看到这一步改了什么。
- 企业微信消息先分清发给谁：推给本人用应用消息，发进业务群用群消息。群消息再按客户机器人实际发的形态选卡片消息或 markdown 消息。
- 手机工作台的横幅与 PC 一致：无底色、无背景图、左对齐。
- 手机工作台和手机看板的版式固定，`hb-wpage` 体内顺序写反会报错：

| 界面 | 版式 | 必有 |
| --- | --- | --- |
| 手机工作台 | 横幅 → 快捷方式（两列）→ 标签页 24 通栏，页签里是卡片列表 | 快捷方式、标签页＋卡片列表 |
| 手机看板 | 横幅 → 标签页 24 通栏，页签里 单指标（两个一行）→ 图表（一行一个）；不放卡片列表，明细另起一屏列表页 | 单指标、至少一张图表 |

  除单指标外一行只放一个组件，`hb-phone` 里写 `hb-row` 会报错；标签页不是必有，没有页签时按同样顺序直接竖排。

## 3. 色彩

- 主色、选项标签的红绿灯语义与 PC 相同，见 [visual-four-principles.md](visual-four-principles.md)。
- 企业微信消息的聊天底色、公众号菜单是微信端的固定样子，不跟皮肤变。
- 门户登录页默认铺极淡的主色纯色底，不渐变，整屏白底会显得空；客户有品牌底图时导出后另换，`plain` 只在用户点名要白底时用。

## 4. 数据与文案

| 界面 | 数量 |
| --- | --- |
| 列表页 | 卡片 3～5 张，每张最多 3 个字段 |
| 手机工作台里的明细 | 卡片 2～3 张；快捷方式 4～6 个 |
| 记录详情／编辑页 | 字段 6～10 个，分 2～3 组 |
| 流程任务列表 | 任务卡 3～4 张 |
| 企业微信消息 | 一屏 1～2 条，每条字段 3～6 行 |
| 门户导航条 | 页签 4 个以内，分组页签放最后 |
| 屏间说明 | 每屏之间 1～2 步，每步一句、18 字以内 |

- 固定 812 高的屏，内容超出时末尾被壳底自然切断，是真机的样子；调条数让它切在行间，不切在字的中腰。
- 多屏之间数据要接得上：消息里的单号、人名、金额，在下一屏的记录页里是同一个。
- 顶栏标题写表名、流程名或群名（群名带人数），不写「手机端」「移动端」这类词。
- 手机号、微信名打码或用虚构值；数据毛边规则见 [anti-sameness.md](anti-sameness.md)。

## 5. 禁止项

- 流程壳里两屏是同一种界面。
- 手机壳里放表格、看板、透视表这类 PC 视图。
- 手机图套 PC 产品壳、左侧导航。
- 画审批时间线或流程条。
- 空态（「没有找到任务」「暂无数据」）。
- 一张图塞四屏以上，或把两屏拼成一屏。
- 横幅加底色、背景图，或居中。
- 企业微信应用消息画了头像和发送者名，或群消息漏了头像和发送者名。

## 6. 检查清单

逐图回答"通过／改过（改了什么）"。

1. 屏数 2～3 屏，一步一屏；没有单屏的手机图（浮层里的手机单屏不在此列）。
2. 多屏时每一屏的界面类型都不同，屏序是一条走得通的路。
3. 每屏的宏顺序与第 1 节对照表一致，该有的底部条（工具栏／操作条／保存条／办理区）没有漏。
4. 列表都是三槽卡片，没有表格；卡片三个槽放的是决策字段。
5. 各屏数量在第 4 节的范围内，被壳底切断的位置在行间。
6. 前后屏的单号、人名、金额对得上。
7. 企业微信消息选对了形态（应用消息／群消息，卡片／markdown）。
8. 通用项（数据像真的、对齐）按 [../canvas/verify-export.md](../canvas/verify-export.md) 的十条表。
