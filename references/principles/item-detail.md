# 自定义详情页：一条记录的全貌

## 1. 定位

- 自定义详情页是一条记录的查看页：官方页面类型 `item_detail`，绑定一张表，页面里的组件默认取"当前记录"。
- 回答三件事：这是哪条记录、走到哪一步了、相关的明细与过程在哪。看数的同时就近决策，不跳页。
- 边界：记录详情弹窗（产品内置弹窗）和标准表单编辑态只在用户明确要求时画；独立自定义详情页默认不套产品壳、不套弹窗。
- 布局属 F 型：通栏信息流，从上到下顺读，靠亲密性分组。

## 2. 布局原则

### 版式（先选一种）

| 版式 | 适用 | 结构（从上到下） |
| --- | --- | --- |
| 双栏式 | 有本记录的数据分析（进度、指标、统计、图表）或快捷表单 | 记录功能区 → 页头卡片 → 步骤条（有则放）→ 分析栏 8 ＋ 主体栏 16：分析栏是一个页签容器，页签内竖叠进度条／单指标／多项统计／图表，快捷表单若有也放这栏；主体栏是一个页签容器，页签内字段组（分组）→ 明细 → 流程 → 动态。分析栏放左（8+16）或放右（16+8）两种 |
| 单栏式 | 没有数据分析和快捷表单 | 记录功能区 → 页头卡片 → 步骤条（有则放）→ 页签容器 24，页签内字段组（一组通栏，或两组 13+11 并排）→ 明细 → 流程 → 动态 |

同一批双栏图分析栏左右交替，默认放左。

选版式：按需求追问的答案从上往下判，命中第一条就停。版式自己定，不问用户，需求单和交付说明里不写版式名。

1. 有本记录的数据分析或快捷表单 → 双栏式。
2. 其余 → 单栏式。

### 顺序（任一版式都守）

记录功能区 → 页头卡片 → 步骤条（有则放）→ 页签容器（主体栏：字段组 → 明细 → 流程 → 动态，流程在前）。双栏时分析栏与主体栏同一行、顶齐；分析栏页签按"资金／进度／审批"这类主题分，主体栏页签按"信息／合同／收款"这类业务分。

### 栅格（24 栅格；画布上边距 48、左右内缩 96、组件间距 20）

| 行 | 配方 | 用法 |
| --- | --- | --- |
| 页头卡片 | 24 | 高 180，标题 20/600＋副标题 14＋关键字段 |
| 步骤条 | 24 | 高 40，箭头段 |
| 双栏 | 分析栏 8 ＋ 主体栏 16（或 16 ＋ 8） | 两栏各一个页签容器；分析栏页签内竖叠进度条（高 2）、单指标（8×5）、多项统计、图表、快捷表单；主体栏页签内字段组每行 4 字段 |
| 字段组并排 | 13＋11 或 15＋9（官方样板） | 单栏式页签内两组字段组并排，左宽右窄 |
| 页签容器 | 24 通栏，高 36～55 | 页签 3～5 个；页签内表格列表 24×16 竖叠 2～3 张，或单指标 8×6 ×3 ＋ 表格 |
| 主体单栏 | 24 | 单栏式；页签容器通栏 |
| 同构子卡 | 8＋8＋8 | 一组同类卡片（多张附件、多个联系人） |

- 双栏两侧底边要齐，落差 >24px 算不齐；修法是给分析栏补一块统计或调栏宽。
- 页签容器内可放字段组、表格列表、单指标、流程；不再套页签容器。
- 页签一律下划线式靠左（hb-tabcard 默认），不用胶囊居中。
- 字段组内按表单规则排：每行最多 4 字段，同组列数一致，不定高字段独占一行（见 [form.md](form.md)）。
- 营销图浮层只从右侧探出，不用左探出（详情页没有左侧导航，左探会压住页头与左栏）。

## 3. 组件选取规则

| 记录要回答的问题 | 组件 | 必有／可选 | 数量与取舍 |
| --- | --- | --- | --- |
| 我能对它做什么 | 记录功能区（产品自带：记录标题＋业务快捷按钮＋编辑／复制／分享／打印／历史／更多／关闭） | 必有，顶部 | 快捷按钮 1～3 个，实底／线框／置灰三态可并存 |
| 这是哪条记录 | 页头卡片 | 必有，首位 | 1；信息字段 1～4 个；不放按钮 |
| 走到哪一步了 | 选项字段-步骤样式 | 有状态流转的单据建议放 | 1 |
| 详细信息、明细、过程各在哪 | 标签页 | 必有，承载主体 | 1～3 个容器，每个 1～4 页签 |
| 记录的字段 | 字段组 | 必有 | 1 个主字段组 ＋ 0～2 个小字段组 |
| 明细行（子表） | 表格列表 | 有主子表时必有 | 列 4～8，行数少于一屏 |
| 审批与协作过程 | 流程执行记录／动态／评论 | 有流程的表必有流程；动态与评论可选 | 各 1 |
| 就近录入 | 快捷表单 | 可选 | 1；放分析栏 |
| 这条记录的数据分析 | 单指标／进度条／折线图／柱状图 | 可选 | 进度条 1～2、单指标 1～2、多项统计 1～2、图表 ≤1，只放与本记录相关的数；全部放分析栏 |

不放的组件：横幅（富文本 大标题预设；详情页的标题在记录功能区，不另放横幅）、筛选组件 筛选、与本记录无关的图表、按钮组 快捷方式格子（操作在记录功能区）。

组件本身怎么选、边界、举例见 [component-guide.md](component-guide.md)。待核：步骤条是否 状态条、流程页签归 流程执行记录 还是 procedure_*。

## 4. 色彩

- 步骤条：已过段主色 25% 底、当前段主色实底白字、未来段白底灰字。
- 流程节点状态：执行中橙、同意绿、驳回红。
- 快捷按钮三态：主动作实底、次动作线框、不可用置灰；同一功能区只有一个实底。
- 颜色只走皮肤 token，见 [../skin/routing.md](../skin/routing.md)。

## 5. 数据与文案

- 页头标题写记录本身（单号＋客户、设备名＋编号），副标题放编号或类型；关键字段选决定业务动作的字段（状态、金额、负责人、日期）。
- 字段总数 6～18 为常态，超过就拆页签。
- 子表行数 5～12，带一处非理想态（缺件、超期、驳回）。
- 流程节点倒序、带耗时；至少一个节点是"执行中"或"驳回"，不全是同意。
- 数据毛边规则见 [anti-sameness.md](anti-sameness.md)。

## 6. 禁止项

- 页头卡片放按钮。
- 套产品壳、一级顶栏、左侧导航、弹窗遮罩（除非用户明确要弹窗）。
- 页签容器里再套页签容器。
- 详情页放横幅、筛选、趋势图。
- 左探出浮层。
- 把"详情侧栏卡／主内容卡"当组件名，它们只是栅格角色。

## 7. 检查清单

逐图回答"通过／改过（改了什么）"。

1. 顶部是记录功能区，页头卡片紧随、通栏、无按钮。
2. 有状态流转的单据带步骤条，当前段唯一。
3. 主体是页签容器，1～3 个，每个 1～4 页签，容器不套容器。
4. 双栏时左查看右操作，两侧底边齐。
5. 字段组每行 ≤4、同组列数一致、不定高字段独占一行。
6. 有流程的表带流程页签且在动态、评论之前。
7. 没有横幅、筛选、趋势图、快捷方式格子。
8. 浮层只在右侧。
