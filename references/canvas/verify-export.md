# 检查与验收（步骤 5 读）

## A. 机检

```bash
python3 scripts/check.py 图.html               # 静态检查；有浏览器时自动加渲染检查
python3 scripts/check.py 图.html --no-render   # 只做静态检查
python3 scripts/check.py 图.html --acceptance  # 起草 B 节的十条
```

**Blocker 必须清零**，High 逐条处理，Medium 逐条判断。几条容易误读的：

- `local-class`（High）：本图样式里定义了 base.css 没有的类，这是自造组件的常见入口；确属一次性布局微调加 `--allow-local` 降为 Nit，多张图都要用就沉淀进 base.css。
- `unknown-token`：`var(--xx)` 在皮肤和 base.css 里都没定义，换肤时会失效；报错带候选名。
- `scale-limit`：表格行数、单指标个数、看板列数超出出图约束（几何问题在无 Chrome 时只能靠约束规避）；是设计判断，确有理由可保留并在验收表第 8 条写明。
- `banner-person-name`（High）：横幅里写了具体人名或问候语；横幅写角色或业务域。
- `stage-no-height`（High）：手写外壳的 `.stage` 没写死高度，导出会算错画布。
- `orphan-span`（Blocker）：`.span-N` 列外面没有 `w-row` 行容器，列会退化成通栏竖叠；并排的组件写进同一个 `<hb-row spans=…>`，不要自己包 span 列。
- `todo-stacked`：待办、我处理的、我发起的各占通栏竖着叠；并排写进一个 `<hb-row spans="8|8|8">`（或 8|16）。
- `card-stretched`：并排里某栏只有一张矮卡，会被拉到与邻栏等高、卡里空一大块；用 `<hb-col>` 在这栏再叠一个组件，或换更高的组件。
- `short-content`：表格列表少于 4 行、透视表少于 3 行，卡里空一截；先在这一栏补一个别的组件，别把一张表灌成一大堆数据。
- `height-unknown`（Nit）：这一行里有组件没有实测高度，等高没检成；肉眼确认两栏底边齐不齐。
- `pivot-as-list`：透视表里装的是记录（大部分格子是文字）；透视表是维度 × 指标的统计，记录列表改 hb-list。
- `slide-height`（High）：演示尺寸的窗口高超过 900，放进 PPT 会被按高度缩小、字看不清；删一块组件或少几行。有浏览器按实测，没有按估算。
- `slide-ratio`：演示尺寸整张图（含浮层探出部分）的宽高比，低于 1.25 报 High，1.25–1.3 报 Medium；推荐 1.3–1.6。只在有浏览器实测时检查。
- `slide-skeleton`（High）：演示尺寸的数据看板底图缺筛选、图表或明细；骨架组件不能为了压高度删掉，超高就减明细行数或压图表高度。
- `slide-thin`（Medium）：演示尺寸整张图宽高比高于 1.75，画面偏扁、内容偏少；底图按完整一页补内容。手机端不查。
- `float-cover`：浮层盖住底图超过四分之一；只截画面的一块局部，或把宽度收小。
- `float-left`：浮层放在了左侧，会盖住导航（详情页是页头与字段）；浮层只从右侧探出。
- `mobile-in-pc`：PC 图里出现手机组件（订单卡、手机工作台、会话流），样式只在 hb-phone 里生效，会散成裸文字；PC 浮层改用 PC 组件。
- `empty-state`：画面里出现「没有找到任务／暂无数据」空态；营销图每块都要有内容。
- `column-short`：同一行里短栏比长栏矮 100px 以上（按 base.css 实测行高估算，不用 Chrome）；单张卡会被拉到等高不算，栏里是单指标行或多张卡才报。只补短的那一栏，先补组件、差 100px 以内才加数据行，不给长栏删内容。
- `empty-gap`（渲染检查）只看布局层——组件之间、组件到画布边缘不许有大片空白；组件内部留白由数据量决定，属产品原样。
- `column-uneven`（渲染检查）：同一行两栏底部落差超过 24px；修法是给短的那栏补数据行或调 `hb-row spans`，不用固定高度硬撑。
- 浏览器认 Chrome，也认 Playwright 装的 Chromium。有浏览器时 `column-short`、`float-cover`、`height-unknown` 这几条静态估算换成实测：并排不齐报 `column-uneven`，浮层遮挡按实测面积报。没有浏览器时打印"渲染检查未执行"，这几项按静态估算。

## B. 人工验收表

机检管不了语义——浮层里的内容是不是底层已经有的、该讲的东西丢没丢、数据像不像真的，这些只能看。**每张图逐条过一遍并把结论写出来，写不出结论就是没验。** `check.py --acceptance` 会把机器能答的先填好。

| # | 检查项 | 判据 |
| --- | --- | --- |
| 1 | 需求单落全 | 需求单里这张图的内容、页面与端、浮层那几块、决定与默认都落在图上；用户在决定里点名要的东西一个不少 |
| 2 | 组件都是真的 | 名称与交互形态对得上登记表（registry.json）与 assets/c1～c5，没有自造组件 |
| 3 | 层次关系对 | 每个组件是"白卡浮在灰底"还是"透明融进容器"，逐一对照结构文件的 `data-measured` |
| 4 | 对齐与选型 | 列数一致、不定高不独占行、状态色走红绿灯、按钮分主/次/警示/置灰、图表选型对 |
| 5 | 浮层不重复底层 | 浮层里的卡片、字段、统计、表格，底层都没出现过 |
| 6 | 浮层底下是完整页面 | 把浮层遮住看底层，仍是一张能独立成立的页面 |
| 7 | 浮层没挡关键内容 | 浮层在右下角，不压住这张图本来要讲的那个字段或那一行 |
| 8 | 信息密度够 | 列表有足够行数、看板指标成组、页签内容填实；scale-limit 有保留的写明理由 |
| 9 | 数据像真的 | 编号有规则且不连号、金额有零头、日期不等距、同一人重复出现、状态分布不均匀 |
| 10 | 整体观感 | 渲染检查没报空隙、裁切、并排不齐、浮层遮挡就算过；这批图第一次用某种版式，或要确认刚改的问题改对了，导一张 PNG 看。没有浏览器时写「未渲染，静态与规模检查已过」 |

交付前按这个格式逐图回报，一图一段：

```
验收 05-库管工作台
1 需求单落全 通过
2 组件都是真的 通过
3 层次关系对 通过
4 对齐与选型 通过
5 浮层不重复底层 改过：浮层原本复制了底层的收支统计，换成回款跟进记录
6 浮层底下是完整页面 通过
7 浮层没挡关键内容 改过：浮层宽度从 880 收到 640，露出明细表的状态列
8 信息密度够 通过
9 数据像真的 通过
10 整体观感 未渲染目检，静态与规模检查已过
```

三条纪律：不合格的写清改了什么，只写"改过"不算；不写"已按清单检查""均无问题"这类总括句；有一条没过就不交付，改完重新回报那一条。

手机图（kind=mobile）的手机壳只用 base.css 里收紧的投影，不要改回窗口级大投影：大投影超出画布会被导出切掉，透明 PNG 贴到有底色的幻灯片上会露出一块灰色矩形。
