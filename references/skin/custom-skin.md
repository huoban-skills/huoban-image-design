# 造皮肤（仅在提取已有样式或新造皮肤时读）

## 从已有样式提皮肤（沿用原样式 / 客户品牌色定制）

新建 `skins/<客户名或报告名>.css`，复制 hb-native.css 全量 token 后只改这些：

- `--primary` / `--primary-deep`：取输入物的主色（品牌色）；deep 取主色加深一档
- `--primary-soft` / `--primary-08`：主色 16% / 8% 透明度
- `--accent` / `--accent-bg`：营销浮层强调色，报告类输入物里找强调色（金、橙类），没有就用 `--primary-deep`
- `--banner-bg`：主色系渐变
- `--tint-*`：主色系浅底

**不要动的**：中性系（页底、卡底、灰阶文字）保持接近原生，界面才像业务系统；彩色状态 token 保持红绿灯语义（绿=成功、蓝=进行、黄=警告、红=危险、灰=未开始），只允许压饱和度去贴报告气质，不允许换语义。这两条来自设计原则（references/principles/visual-color.md）。

**主色撞状态色时怎么办**：品牌色本身就是红/绿/黄时（消防红、环保绿等），主色和状态色会混淆，用户分不清"这是品牌还是在报警"。做法是把撞车的那个状态色推开一档拉开距离（见 burgundy-white.css：主色深酒红 #6D1F2C，危险红推亮为 #C0453C），而不是改状态语义。

**新皮肤底线**（与报告侧 check_skin.py 同一标准）：浅色皮肤底色近白不发黄不发浊（通道 ≥ #EC、通道差 ≤ 12、R-B ≤ 10），强调色清晰不荧光，不用米黄/大地/莫兰迪浊底。官网 skill 的其余风格（玻璃拟态、粗野主义、赛博朋克等）涉及材质与结构效果或 B 端不宜，不入库；确有需要时按本文件的 token 契约现造。

## 取色尺（新皮肤的深浅关系标准）

手写或生成新皮肤时，token 之间的明暗关系不凭手感，按 Radix Colors 的 12 级语义取（每个色相从浅到深 12 级，各级有固定用途；Tailwind 色板可当默认取色库，级数换算：Radix 1-12 ≈ Tailwind 50→950 的对应梯度）：

| Radix 级 | 用途 | 对应 token |
|---|---|---|
| 1-2 | 应用背景 | --page-bg、--backdrop |
| 3 | 组件常态底 | --primary-08（选中行）、--field-bg / --filter-bg |
| 4-5 | 组件选中/按下底 | --primary-soft（选中页签）、--tint-* |
| 6-7 | 边框 | --line |
| 9 | 纯色实底（最高饱和） | --primary、--c-*（彩底标签/按钮） |
| 10 | 实底加深 | --primary-deep（顶栏） |
| 11-12 | 文字（次要/主要） | --ink-45 / --ink-85（--ink-65/25 在 11 与 12、2 与 11 之间内插） |

不在尺内、按各皮肤气质自定的：--banner-bg 渐变、--accent 强调、两个 shadow、--font。
Review 新皮肤＝逐 token 对表：选中底必须明显浅于边线、边线浅于实底、暗色皮肤同表反向套用。

## Token 契约

皮肤文件必须提供 base.css 引用的全部变量（以 hb-native.css 为准的完整清单）。少一个变量对应组件就会裸奔，新皮肤写完先拼一张列表页冒烟验证。

**--backdrop 现为备用 token**：画布已改透明，衬底不再绘制；token 保留以维持契约完整。

**大屏 token 不在契约里**：`--screen-*`（底色、描边、角标色、光带色、图表系列色）由 base.css 的五个 `.screen.theme-*` 给全，皮肤不必提供。皮肤要改写成 `body .screen { --screen-…: …; }`——皮肤拼在 base.css 之前，同特异度的 `.screen` 盖不住。
