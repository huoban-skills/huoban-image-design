# 需求追问与需求单（步骤 1 读）

读材料，用户在对话或材料里明说的记为已定，其余按下面三轮提问；画布类型、角色、样式是用户的决定，材料写得再细也替不了他，第 1 轮总要问。每轮一条消息，发出后结束回复等用户答，不把三轮合并，不跳过追问直接给需求单。每一题都是用户日常会做的业务选择，候选答案从材料和行业惯例里给，不问"颗粒度""维度"这类分析词。每题带推荐答案，用户不表态就按推荐。不要用户提供真实数据：默认没有工作区，字段名和数据按材料里的行业自己编，只在第 3 轮问量级、时间范围和脱敏口径。

## 三轮维度

### 第 1 轮（任何图都问）

| 顺序 | 定什么 | 问法（示例取仓库场景） |
| --- | --- | --- |
| 1 | 画布类型 | 这张图是放进方案报告讲给客户听，还是客户要照着在伙伴云里搭？推荐：材料是报告就按营销类 |
| 2 | 页面类型与端、张数 | 画哪个页面：库管工作台、库存看板还是出库单详情页？PC 还是手机？一张还是一组？推荐：材料里讲得最多的那个页面 |
| 3 | 角色 | 这页给库管、仓库主管还是采购用？推荐：材料里的主要角色 |
| 4 | 样式 | 按 [skin/routing.md](skin/routing.md) 判定输入物：带样式的输入物问是否沿用；不带样式的给首选、备选和自定义三个选项；报告已经选了皮肤就直接用同名皮肤，不问 |

页面类型题的选项从材料里出现的页面写，让用户一眼看出画哪个。"给所有人"要追问到一个角色。

### 第 2 轮（按页面类型分支，只问命中的一支）

| 页面类型 | 定什么 | 问法示例 |
| --- | --- | --- |
| 列表页 | 视图形态 | 物资档案用网格表格、按状态分列的看板、按日期的日历还是甘特？推荐：网格。筛选、工具栏、列字段按行业默认，不问 |
| 表单 | 展示哪些字段、怎么分组、有没有子表 | 出库单弹窗分几组、有没有明细子表？推荐：基本信息 ＋ 出库明细子表 ＋ 审批信息。只有弹窗一种，新建与编辑同一形态 |
| 详情页 | 这是哪条记录、有没有流程或状态流转、有没有明细子表、页签怎么分 | 出库单详情要不要显示审批进度？明细、流程、动态各放一个页签还是合并？推荐：有流程就放步骤条；明细、流程、动态各一个页签 |
| 工作台 | 这个角色一天要发起什么、要处理什么、参不参与流程 | 库管每天从这页发起什么（扫码出库、扫码入库、盘点）？要处理什么（出库审批待办）？参不参与审批？推荐：按材料里的流程给 |
| 数据看板／大屏 | 结果指标、过程指标、对比维度（见下） | 结果指标 4～6 个，过程指标与对比维度各 3～5 个；筛选范围自己定，不问 |
| 手机端 | 把上面命中的那一支问一遍 | — |

数据看板三项指标的问法，选项从材料里的业务数字给：

| 指标 | 问法 | 选项来源 |
| --- | --- | --- |
| 结果指标 | 你核心的结果指标是哪几个？推荐：出库及时率、库存周转天数、盘点差异率 | 销售额、目标完成率、按时交付率、良品率 |
| 过程指标 | 达成它要经过哪几个环节，各环节看什么数？推荐：审批时长、拣货时长、复核差错数 | 顺利推进＝转化率类，推进快慢＝时间类，异常分支＝风险类 |
| 对比维度 | 按哪几个维度比？推荐：谁对指标负责就按谁切 | 人员、区域、产品、渠道、批次 |

三项缺一个链路就断：只有结果没有过程，看到问题找不到原因；过程指标必须从结果指标拆出来；缺对比维度，整体持平也看不出哪个团队暴跌。

### 第 3 轮（依赖前两轮）

| 条件 | 定什么 | 问法示例 |
| --- | --- | --- |
| 营销类 | 浮层突出什么（只能是底层没有的内容） | 浮层强调哪个卖点：扫码出库后库存实时变化，还是审批一键通过？推荐：材料里最强调的那个 |
| 营销类且手机端 | 讲几步流程（1 屏用单屏壳，2～3 屏用流程壳）、每屏哪一步、哪屏是企微会话 | 手机图讲几步：只看审批页一步，企微收到待办 → 点开审批两步，还是再加出库单已生成三步？推荐：有"从哪来到哪去"就两步。超过 3 步拆两张图 |
| 工作台／看板 | 横幅形态、层次 | 横幅无背景、纯色还是背景图卡片？层次白底描边还是浅底白卡？推荐：无背景、白底描边，一句话确认 |
| 详情页 | 层次 | 层次白底描边还是浅底白卡？推荐：白底描边，一句话确认 |
| 任何图 | 数据文案：数字量级、时间范围、脱敏 | 数字按月出库几百单还是几千单编？人名用常见姓名还是材料里的真实姓名？推荐：按材料规模；常见姓名 |

## 问法格式

一轮一条消息，把当轮维度问完就停，等用户答完再问下一轮。有选择框工具（如 AskUserQuestion、request_user_input）就用工具，一道提问一道题；没有就用文字版，每个选项单独一行，选项从材料和行业惯例里给，每题不超过 4 个，推荐项放 A 并标（推荐），末项留"其他"。

第 1 轮的文字版长这样（仓库场景，换客户时换成材料里的业务）：

```
出图前先确认几点：

1. 这批图用在哪？
   A. 放进方案报告讲给客户听（推荐）
   B. 客户要照着在伙伴云里搭
   C. 其他（请补充）

2. 先画哪个页面？
   A. 库管工作台，PC（推荐）
   B. 库存看板，PC
   C. 出库审批，手机
   D. 其他（请补充）

3. 这页给谁用？
   A. 库管（推荐）
   B. 仓库主管
   C. 采购
   D. 其他（请补充）

4. 配色？
   A. 用推荐皮肤晨光蓝（推荐）
   B. 用品牌色（请给色号）
   C. 其他（请补充）
```

用户答完若引出新问题（选了"其他"、回答与材料矛盾、某一支需要展开），再问一轮，直到没有待明确的项才汇需求单。

## 需求单

三轮问完，汇成需求单让用户确认；多张图列在一张表里一次确认。**没拿到确认不进入步骤 2。** 格式对内对外一致，huoban-solution-report 的调用也是这个格式。整批共用的写在表上方一行，逐图的写进表：

```
画布：营销类 ｜ 皮肤：晨光蓝 ｜ 数据：近一个月，月出库几百单，人名常见姓名
```

内容按页面从上到下的分区写，一个分区一句"分区名：放什么"，浮层单独一句：

| 图名 | 内容（含浮层） | 组件 |
| --- | --- | --- |
| 库管工作台（PC） | 横幅：库管工作台，一句话介绍；单指标：本月出库单数、待审批单数、库存预警数、盘点差异数；快捷入口：扫码出库、扫码入库、盘点；待办：出库审批、我处理的、我发起的；页签：我的出库单、我的入库单；浮层：扫码出库后库存实时变化 | 横幅、单指标 4 个、按钮组、多项统计「待办」＋我处理的＋我发起的、标签页 |
| 出库审批（手机） | 第一屏：企微会话收到出库审批待办；第二屏：点开审批页，核对明细后通过 | 企微会话流、任务办理页 |
