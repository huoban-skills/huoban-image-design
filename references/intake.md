# 需求追问与需求单（步骤 1 读）

只问会改变图上讲什么的决定，其余自己定。四条原则：

| 原则 | 怎么做 |
| --- | --- |
| 事实自己定，决定问用户 | 材料里写了的、行业默认的、本 skill 有规矩的（页面类型、端、版式、底色、组件、数据口径）都不问，直接定；只问"讲什么、讲到哪一步、突出什么"这类决定 |
| 一轮只问前置已定的题 | 依赖本轮答案的题放下一轮；同一轮的题互不依赖 |
| 每题给推荐和一句理由 | 理由指向材料（"材料里督导的主要动作就是这两项"），不凭空推荐；轮末一行汇总，用户回"按推荐"整轮采纳 |
| 没问的写成默认，不默默假设 | 自己定的都进需求单"决定与默认"列并标（默认），终稿里用户能一眼改 |

发消息的纪律：一轮一条消息，题全部发出即停，等用户答完再发下一条；用户漏答的按推荐记，不追问；确要再问就把题重写一遍，不说"上面的题"。不要用户提供真实数据。

## 流程：四种消息

| 序 | 消息 | 内容 | 停下等什么 |
| --- | --- | --- | --- |
| 1 | 定盘子 | 画布、配色两题，加 0～2 道清单题（触发条件见下） | 用户答题 |
| 2 | 需求单初稿 | 需求单格式，决定与默认列全写"待问"，不带任何题 | 用户增删图，或回"没有" |
| 3… | 逐图决定 | 每小轮 3 张图的题，一题一个编号；有依赖的题推到下一小轮 | 用户答题，直到题库问空 |
| 末 | 终稿 | 和初稿同一格式，决定与默认列填实，问"按这份做吗" | 用户回"确认" |

闸门三条写在 SKILL.md 步骤 1。huoban-solution-report 传来的出图需求单已写明角色和图时，第 1 条消息的清单题跳过，其余照走。

## 第 1 条消息：定盘子

| 题 | 问法（仓库场景示例，换客户时换成材料里的业务） | 注（给模型看，不发给用户） |
| --- | --- | --- |
| 画布类型 | 这批图用在哪？A 放进方案报告讲给客户听（推荐：材料是给客户的方案） B 客户要照着在伙伴云里搭 C 其他 | — |
| 配色 | 配色？A 用推荐皮肤晨光蓝（推荐：仓储物流场景强调效率） B 用备选皮肤藏蓝金 C 用品牌色（请给色号） | 推荐与备选按 [skin/routing.md](skin/routing.md) 选；带样式的输入物改问是否沿用；报告已选皮肤就直接用同名，不问 |

消息模板（清单题按触发条件增减，没有就只发两题）：

```
出图前先确认几点：

1. 这批图用在哪？
   A. 放进方案报告讲给客户听（推荐：材料是给客户的方案）

   C. 用品牌色（请给色号）
3. 这套图讲谁的操作、给谁看？可多选

```

图的清单由主角、要讲哪些事两个维度，再按颗粒度切出来。颗粒度随画布定（见"自己定的默认项"），不问；另外两个维度材料定不下来才问：

| 维度 | 决定什么 | 什么时候问 | 问法 | 注（不发给用户） |
| --- | --- | --- | --- | --- |
| 主角 | 图分几条线，不同角色各自成线 | 材料里的角色超过 3 个，或只说"给所有人看" | 这套图讲谁的操作、给谁看？可多选：A 库管（推荐：材料里痛点集中在出入库） B 仓库主管（推荐：审批环节在他手上） C 老板 D 采购 E 财务 | 角色从材料里取，痛点最集中的标推荐 |
| 要讲哪些事 | 每条线上有几个点 | 主线之外还有看结果的诉求或独立支线；只有一条主线时不问，全列 | 除了出入库主线，这几件要不要讲？可多选：A 老板看库存预警（推荐：材料点名要预警） B 采购按预警补货 C 财务月末对账 D 都不要 | 选项分三类给：主线环节、看结果、平行支线 |

## 第 2 条消息：需求单初稿

按主角分线，每条线上放选中的事，再按颗粒度合并或拆开；每一行按这件事怎么办定页面类型和端，张数是算出来的，不另估。页面类型只有 SKILL.md 路由表第一列那七种，不自创；这里只决定"这件事落到哪一种"：

| 这件事怎么办 | 页面类型 |
| --- | --- |
| 角色一天的入口，从这里发起和处理 | 工作台 |
| 从一批记录里找、筛、批量处理 | 列表页 |
| 打开一条记录看清楚再办：审批、复核、跟进、催办 | 详情页 |
| 填一张单 | 并入发起它的工作台（按钮组件）或手机端流程；用户点名要表单时才出表单编辑页 |
| 看数、比出问题在哪 | 数据看板；用户或材料明说要大屏、挂墙、投屏时才是数据大屏 |
| 上面任一件事在手机上办 | 手机端：按步骤办（签到、逐项检查、拍照提交）画 2～3 屏流程，只看一屏（列表、首页、一条记录）画单屏 |

组件列只写路由表"说明"列给的骨架（工作台就是横幅、单指标、按钮组件、待办、标签页），再加材料里点名的东西；逐个组件怎么选到步骤 2 读该页面原则的组件表时再定，初稿不需要读原则文档。

按下文"需求单"一节的格式发初稿，用户回复后第 3 条才另起。

## 第 3 条起：逐图决定

题库一行一题，只有决定，没有形态。一张图按页面类型把该问的行都问到，一题一个编号、题干前带图名、选项各占一行；每小轮 3 张图，一张图的题同轮问完。前置一列写了"下一轮"的依赖题例外：等前置答完，排在下一小轮最前面，不占 3 张图的名额。

| 问谁 | 决定 | 问法示例 | 前置 | 注（不发给用户） |
| --- | --- | --- | --- | --- |
| 列表页 | 视图形态 | 物资档案：用哪种视图？A 网格表格（推荐：档案要看全字段） B 按状态分列的看板 C 按日期的日历 D 甘特 E 其他 | 无 | 推荐按 [principles/list-view.md](principles/list-view.md) 的视图表 |
| 表单编辑页 | 分几组、有没有子表 | 出库单：表单分几组？A 基本信息 ＋ 出库明细子表 ＋ 审批信息（推荐：材料里一单多品） B 只放基本信息 C 其他 | 无 | 用户点名要表单时才有这张图 |
| 工作台 | 发起什么 | 库管工作台：每天从这页发起什么？A 扫码出库、扫码入库、盘点（推荐：材料里的三个高频动作） B 只有出入库 C 其他 | 无 | — |
| 工作台 | 处理什么 | 库管工作台：要处理什么？A 出库审批待办（推荐：材料说主管审批库管执行） B 不参与审批，只看自己的单 C 其他 | 无 | — |
| 工作台 | 查什么 | 库管工作台：平时在这页查什么？A 今天的出入库记录和库存台账（推荐：材料说库管要随时查库存） B 只查自己经手的单 C 其他 | 无 | 答案落到表格列表和标签页 |
| 详情页，且本记录既有数字、又有 3 张以上关联记录 | 字段旁边放什么 | 出库单详情：字段之外，这条记录还要一眼看到什么？A 它自己的数字：数值／计算字段、进度、1～2 张图表（推荐：材料里主管审批前要看金额与库存） B 挂在它下面的关联记录：跟进、售后、明细子表 C 其他 | 无 | 答 A 用双栏式，答 B 用主从式；其余详情页按 [principles/item-detail.md](principles/item-detail.md) 的版式表直接定，不问 |
| 详情页 | 页签放什么 | 出库单详情：下面的页签放什么？A 出库明细、审批记录、动态（推荐：材料里一单多品且要留痕） B 只放出库明细 C 其他 | 无 | — |
| 数据看板／大屏 | 结果指标（看板 4～6 个，大屏 4 或 8 个） | 库存看板：核心结果指标是哪几个？A 出库及时率、库存周转天数、盘点差异率、预警品种数（推荐：材料里老板最关心这四个） B 其他 | 无 | 选项从材料里的业务数字给 |
| 数据看板／大屏 | 过程指标 1～3 个 | 库存看板：达成这几个结果要经过哪些环节，各看什么数？A 审批时长、拣货时长（推荐：出库及时率卡在这两步） B 其他 | 下一轮：结果指标 | 从上轮定的结果指标拆 |
| 数据看板／大屏 | 对比维度 1～2 个 | 库存看板：按哪几个维度比？可多选，最多 2 个：A 按仓库（推荐：仓库主管对指标负责） B 按业务员 C 按物资类别 | 下一轮：结果指标 | 谁对指标负责就按谁切 |
| 手机端 | 讲几步 | 出库审批：手机图讲几步？A 两步：企微收到待办 → 点开审批（推荐：材料强调在企微里办） B 一步，只看审批页 C 三步：企微通知 → 审批 → 出库单已生成 D 其他 | 无 | 超过 3 步拆两张图 |
| 营销类，且材料里的卖点不止一个 | 浮层突出什么 | 库管工作台：浮层强调哪个卖点？A 扫码出库后库存实时变化（推荐：材料反复提库存不准） B 审批一键通过 C 其他 | 无 | 浮层规则见 [canvas/marketing.md](canvas/marketing.md) |

```

   B. 只有出入库
   C. 其他

   C. 其他

```

选项每题不超过 5 个，推荐放前面并带理由。单选题末项留"其他"；多选题写明"可多选"，不留"其他"，靠轮末那句让用户补。选择框工具一次能装下整轮才用，装不下用文字版。

## 自己定的默认项

这些不问，终稿里写进"决定与默认"列并标（默认）：

| 项 | 默认 |
| --- | --- |
| 页面类型与端 | 按第 2 条消息的映射表定；版式按各页面原则的版式表定，不写进需求单 |
| 颗粒度 | 放进方案报告时每个环节一张，讲清动作；照着搭时每个角色一张，一页把他的事讲完 |
| 页面底色、横幅 | 白底、组件描边；横幅无背景 |
| 筛选、工具栏、列字段 | 按行业惯例 |
| 详情页状态条 | 有状态流转的单据才放 |
| 手机端企微会话屏 | 材料提到企微或公众号通知时，第一屏是企微会话 |
| 浮层 | 材料只有一个卖点时直接用它；两张卡以内 |
| 数据口径 | 数字按材料里的规模编，时间近一个月，人名用常见姓名 |
| 手机竖图 | 嵌报告时限宽居中（约 360px） |

## 需求单

初稿和终稿是同一个格式，整条消息只有四部分：标题行、共用一行、需求单表、末句。不分节，不加说明段，不另列要点，表后不接题。

```
需求单{初稿／终稿}：
{共用一行：画布 ｜ 皮肤 ｜ 数据}

{需求单表}

{末句}
```

| 部分 | 初稿 | 终稿 |
| --- | --- | --- |
| 标题行 | 需求单初稿： | 需求单终稿： |
| 决定与默认列 | 一律写"待问" | 问出来的写"答：…"，自己定的写上并标（默认），不能再有"待问" |
| 末句 | 哪几张不要、还缺哪张，直接说；没有就回"没有"，我再逐图问。 | 按这份做吗？回复"确认"开始出图。 |

表的前四列两稿写法一样：

| 列 | 写什么 |
| --- | --- |
| 图名 | 界面名，用材料里的叫法 |
| 内容 | 一句话：某角色在这个界面上能干什么，写给用户看的 |
| 页面与端 | 路由表第一列七种之一（列表页、表单编辑页、详情页、工作台、数据看板、数据大屏、手机端）加 PC；手机端注明单屏或几屏流程 |
| 组件 | 路由表"说明"列的骨架，加材料里点名的东西 |

初稿示例：

需求单初稿：
画布：营销类 ｜ 皮肤：晨光蓝 ｜ 数据：近一个月，月出库几百单，人名常见姓名

| 图名 | 内容 | 页面与端 | 组件 | 决定与默认 |
| --- | --- | --- | --- | --- |
| 库管工作台 | 库管一进来就能扫码出入库、发起盘点，看到待审批的出库单和今天的入库数 | 工作台，PC | 横幅、单指标、按钮组件、待办、标签页 | 待问 |
| 出库审批 | 主管在企微里收到待办，点开核对明细后一键通过 | 手机端，两屏流程 | 企业微信会话、记录页、任务办理区 | 待问 |
| 库存预警看板 | 老板一眼看到周转天数和预警品项，按仓库比出问题出在哪 | 数据看板，PC | 横幅、筛选、单指标、图表行、预警品项明细 | 待问 |

哪几张不要、还缺哪张，直接说；没有就回"没有"，我再逐图问。
