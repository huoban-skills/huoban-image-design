# 需求追问与需求单（步骤 1 读）

先弄明白这批图要替方案讲清什么，再据此拟需求单让用户确认。纪律：

- 页面类型、端、版式由本 skill 按场景定，不让用户挑。
- 用户在对话或材料里明说的记为已定，其余要问；画布类型、配色是用户的决定，材料写得再细也替不了他；图的清单按三个维度算，定不下来的维度才问。
- 每轮一条消息把当轮的题全部发出，发出后结束回复等用户答；不逐题追问，不把几轮合并，不跳过追问直接给需求单。
- 用户只答了部分题（含没在选择框里答、直接打字答的），答了的照记，剩下的按推荐项处理并在需求单里注明，不再追问；确要再问时把题和选项重新写一遍，不说"上面的题"。
- 第 2 轮每小轮 5 题，一条消息一小轮。
- 不要用户提供真实数据，字段名和数据按材料里的行业自己编。

## 第 1 轮：定用途、配色和图的清单

一条消息发完：固定两题，加 0～3 道清单题。清单题各有触发条件，材料能定的不问；huoban-solution-report 传来的出图需求单已写明角色和图，清单题全跳。

| 顺序 | 定什么 | 问法（仓库场景示例，换客户时换成材料里的业务） |
| --- | --- | --- |
| 1 | 画布类型 | 这批图用在哪？A 放进方案报告讲给客户听（推荐） B 客户要照着在伙伴云里搭 C 其他 |
| 2 | 配色 | 配色？A 用推荐皮肤晨光蓝（推荐） B 用备选皮肤藏蓝金 C 用品牌色（请给色号）。皮肤按 [skin/routing.md](skin/routing.md) 选：带样式的输入物改问是否沿用；报告已选皮肤就直接用同名，不问 |

图的清单由三个维度算出来：谁、讲哪些事、切多细。页面类型和端从"事"推出，不是维度。

| 维度 | 决定什么 | 什么时候问 | 问法 |
| --- | --- | --- | --- |
| 主角 | 图分几条线，不同角色各自成线 | 材料里的角色超过 3 个，或只说"给所有人看" | 这套图讲谁的操作、给谁看？可多选：A 库管（推荐） B 仓库主管（推荐） C 老板 D 采购 E 财务 |
| 要讲哪些事 | 每条线上有几个点 | 主线之外还有看结果的诉求或独立支线；只有一条主线时不问，全列 | 除了出入库主线，这几件要不要讲？可多选：A 老板看库存预警（推荐） B 采购按预警补货 C 财务月末对账 D 都不要。选项分三类给：主线环节、看结果、平行支线 |
| 颗粒度 | 张数 | 任一角色名下的事超过 2 件 | 怎么切图？A 每个环节一张，讲清动作（推荐，方案报告用） B 每个角色一张，一页把他的事讲完（要照着搭时推荐） |

## 拟需求单初稿（第 2 条消息：只发初稿）

第 1 轮答完，按主角分线，每条线上放选中的事，再按颗粒度合并或拆开，每一行按场景定页面类型和端：角色一天的入口 → 工作台；办一件事 → 手机流程或列表页；看一条记录 → 详情页；看数 → 数据看板或大屏。张数是这样算出来的，不另估。

初稿只是让用户增删图，不是确认。这条消息只有需求单，不带任何题，发出即停：

```
需求单初稿，先看图对不对：
{共用一行}
{需求单表，细节列一律写"待问"}
哪几张不要、还缺哪张，直接说；没有就回"没有"，我再逐图问细节。
```

不写"确认吗"，不写"确认后开始制作"：这时候还没问完，用户回一句"可以"也不算确认，只表示图的清单定了。

整批共用的写在表上方一行，逐图的写进表。内容一列是一句话：某角色在这个界面上能干什么，写给用户看的，不列组件不写栅格。细节一列放第 2 轮问出来的答案，初稿阶段写"待问"。

```
画布：营销类 ｜ 皮肤：晨光蓝 ｜ 数据：近一个月，月出库几百单，人名常见姓名
```

| 图名 | 内容 | 页面与端 | 组件 | 细节 |
| --- | --- | --- | --- | --- |
| 库管工作台 | 库管一进来就能扫码出入库、发起盘点，看到待审批的出库单和今天的入库数 | 工作台，PC | 横幅、单指标 4 个、按钮组、多项统计「待办」＋我处理的＋我发起的、标签页 | 发起：扫码出库、扫码入库、盘点；处理：出库审批待办；浮层：扫码后库存实时变化；标题区无背景，白底描边 |
| 出库审批 | 主管在企微里收到待办，点开核对明细后一键通过 | 两屏流程，手机 | 企微会话流、任务办理页 | 两步：企微收到待办 → 点开审批 |
| 库存预警看板 | 老板一眼看到周转天数和预警品项，按仓库比出问题出在哪 | 数据看板，PC | 横幅、筛选、单指标 4 个、折线图、条形图、表格列表 | 结果：出库及时率、周转天数、盘点差异率；过程：审批时长、拣货时长；对比：按仓库；白底描边 |
| 补货申请 | 采购按预警品项发起补货，填数量和到货日期 | 表单编辑页，PC | 字段组、明细子表、提交按钮 | 三组：基本信息 ＋ 补货明细子表 ＋ 审批信息 |

手机竖图嵌报告时限宽居中（约 360px），需求单里注明。

## 第 2 轮：逐图补细节

用户增删完图，另起消息开始第 2 轮。第 2 轮不能跳过：每张图至少问一题。每张图按页面类型问那一支的题（下表），营销类再问浮层突出什么；筛选、工具栏、列字段这类能按行业默认的不问。按需求单顺序把题排成一列，每 5 题一小轮，一小轮一条消息、答完再发下一小轮；一张图的题不拆到两轮，凑不满 5 题就少问几题。数据文案题整批问一次，放最后一小轮。

每小轮的写法：一题一个编号，选项各占一行；一张图有几题就占几个编号，不把"浮层突出什么、标题区要不要背景"挤进同一条里。

```
第 2 轮细节，第 {k}/{m} 小轮（5 题）：

1. 督导工作台：每天从这页发起什么？
   A. 到店打卡、常规巡检（推荐）
   B. 只看自己的巡检任务
   C. 其他
2. 督导工作台：浮层突出什么？
   A. 到店定位打卡弹窗（推荐）
   B. 整改审核弹窗
   C. 其他
3. 整改闭环追踪：看板按什么分列？
   …

按推荐就是 {1A、2A、3A}，回复"按推荐"即可；要改哪题单说。
```

| 页面类型 | 定什么 | 问法示例 |
| --- | --- | --- |
| 列表页 | 视图形态 | 物资档案用哪种视图？A 网格表格（推荐） B 按状态分列的看板 C 按日期的日历 D 甘特。筛选、工具栏、列字段按行业默认，不问 |
| 表单编辑页 | 展示哪些字段、怎么分组、有没有子表 | 出库单的表单编辑页分几组？A 基本信息 ＋ 出库明细子表 ＋ 审批信息（推荐） B 只放基本信息 C 其他。新建与编辑同一形态 |
| 详情页 | 有没有流程或状态流转、有没有明细子表、页签怎么分 | 出库单详情要不要显示审批进度？A 要，顶部放状态条（推荐） B 不要。明细、流程、动态怎么放？A 各一个页签（推荐） B 合并成一个页签 C 其他 |
| 工作台 | 这个角色一天要发起什么、要处理什么、参不参与流程 | 库管每天从这页发起什么？A 扫码出库、扫码入库、盘点（推荐） B 只有出入库 C 其他。要处理什么？A 出库审批待办（推荐） B 不参与审批，只看自己的单 |
| 数据看板／大屏 | 结果指标、过程指标、对比维度（问法见下表） | 结果指标 4～6 个，过程指标与对比维度各 3～5 个；筛选范围自己定，不问 |
| 手机端 | 讲几步流程（1 屏用单屏壳，2～3 屏用流程壳）、每屏哪一步、哪屏是企微会话 | 手机图讲几步？A 两步：企微收到待办 → 点开审批（推荐） B 一步，只看审批页 C 三步：企微通知 → 审批 → 出库单已生成。超过 3 步拆两张图 |

数据看板三项指标的问法，选项从材料里的业务数字给：

| 指标 | 问法 | 选项来源 |
| --- | --- | --- |
| 结果指标 | 你核心的结果指标是哪几个？A 出库及时率、库存周转天数、盘点差异率（推荐） B 其他 | 销售额、目标完成率、按时交付率、良品率 |
| 过程指标 | 达成它要经过哪几个环节，各环节看什么数？A 审批时长、拣货时长、复核差错数（推荐） B 其他 | 顺利推进＝转化率类，推进快慢＝时间类，异常分支＝风险类 |
| 对比维度 | 按哪几个维度比？A 按仓库（推荐） B 按业务员 C 按物资类别 D 其他。谁对指标负责就按谁切 | 人员、区域、产品、渠道、批次 |

形态与数据，按条件问：

| 条件 | 定什么 | 问法示例 |
| --- | --- | --- |
| 营销类 | 浮层突出什么（只能是底层没有的内容） | 浮层强调哪个卖点？A 扫码出库后库存实时变化（推荐） B 审批一键通过 C 其他。推荐材料里最强调的那个 |
| 工作台／看板 | 页面顶部标题区（富文本「大标题」预设，本 skill 称横幅）的形态、页面底色 | 页面顶部的标题区要不要背景？A 无背景（推荐） B 纯色底 C 背景图卡片。页面底色？A 白底、组件描边（推荐） B 浅灰底、组件白卡 |
| 详情页 | 页面底色 | 页面底色？A 白底、组件描边（推荐） B 浅灰底、组件白卡 |
| 任何图 | 数据文案：数字量级、时间范围、脱敏 | 数字按什么规模编？A 月出库几百单（推荐） B 几千单 C 其他。人名？A 常见姓名（推荐） B 材料里的真实姓名 |

全部答完，把答案写进每张图的细节列，发终稿需求单让用户确认；选了"其他"、回答与材料矛盾、某张图还定不下来，就再问一轮。终稿消息固定写法：

```
需求单终稿：
{共用一行}
{需求单表，细节列全部填实，没有"待问"}
按这份做吗？回复"确认"开始出图。
```

**闸门三条同时满足才算确认：第 2 轮每张图都问过、细节列没有"待问"、用户对终稿回了确认。** 初稿被认可不算，第 1 轮答完直接开干更不算。格式对内对外一致，huoban-solution-report 的调用也是这个格式。

## 问法格式

一轮的题一次发完。选择框工具（如 AskUserQuestion）一次调用能装下整轮所有题就用它，一次只能问一题的不用；工具不可用或装不下时用文字版，一轮一条消息，题目和选项写在正文里。文字版格式：

```
出图前先确认几点：

1. {问题}？
   A. {推荐项}（推荐）
   B. {选项}
   C. 其他（请补充）

2. ...

按推荐就是 {1A、2AB、3A}，回复"按推荐"即可；要改哪题单说。
```

选项从材料和行业惯例里给，每题不超过 5 个；推荐项放前面并标（推荐），末项留"其他"；多选题在题目里写明"可多选"。每轮最后一行固定把各题推荐项汇总成一串（多选题把推荐的几个字母连写），用户回"按推荐"就整轮按这串记；这一行是格式的一部分，选择框工具版也要在题目说明里带上。
