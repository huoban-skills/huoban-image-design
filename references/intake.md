# 需求追问与需求单（步骤 1 读）

先弄明白这批图要替方案讲清什么，再据此拟需求单让用户确认；页面类型、端、版式由本 skill 按场景定，不让用户挑。用户在对话或材料里明说的记为已定，其余要问；画布类型、要讲的事、配色是用户的决定，材料写得再细也替不了他。每轮一条消息，发出后结束回复等用户答；不把几轮合并，不跳过追问直接给需求单。不要用户提供真实数据，字段名和数据按材料里的行业自己编。

## 第 1 轮：弄明白出图需求

| 顺序 | 定什么 | 问法（仓库场景示例，换客户时换成材料里的业务） |
| --- | --- | --- |
| 1 | 画布类型 | 这批图用在哪？A 放进方案报告讲给客户听（推荐） B 客户要照着在伙伴云里搭 C 其他 |
| 2 | 要讲清哪几件事、主角是谁 | 这套图要讲清哪几件事？A 库管扫码出入库 → 主管审批出库 → 老板看库存预警（推荐） B 只讲库管扫码出入库和主管审批 C 其他（要加或去掉的环节）。选项从材料里的流程和痛点拟，一套就是一条故事线 |
| 3 | 配色 | 配色？A 用推荐皮肤晨光蓝（推荐） B 用备选皮肤藏蓝金 C 用品牌色（请给色号）。皮肤按 [skin/routing.md](skin/routing.md) 选：带样式的输入物改问是否沿用；报告已选皮肤就直接用同名，不问 |

"环节：角色"的选项从材料里的业务流程和痛点拟，一套就是这次方案要靠图讲的故事线；"给所有人看"要追问到一个角色。

## 拟需求单

第 1 轮答完，把每个环节落成一张图：按场景定页面类型和端（角色一天的入口 → 工作台；办一件事 → 手机流程或列表页；看一条记录 → 详情页；看数 → 数据看板或大屏），写成需求单初稿，和第 2 轮问题放在同一条消息里发给用户。

整批共用的写在表上方一行，逐图的写进表。内容一列是一句话：某角色在这个界面上能干什么，写给用户看的，不列组件不写栅格。

```
画布：营销类 ｜ 皮肤：晨光蓝 ｜ 数据：近一个月，月出库几百单，人名常见姓名
```

| 图名 | 内容 | 页面与端 | 组件 |
| --- | --- | --- | --- |
| 库管工作台 | 库管一进来就能扫码出入库、发起盘点，看到待审批的出库单和今天的入库数 | 工作台，PC | 横幅、单指标 4 个、按钮组、多项统计「待办」＋我处理的＋我发起的、标签页 |
| 出库审批 | 主管在企微里收到待办，点开核对明细后一键通过 | 两屏流程，手机 | 企微会话流、任务办理页 |
| 库存预警看板 | 老板一眼看到周转天数和预警品项，按仓库比出问题出在哪 | 数据看板，PC | 横幅、筛选、单指标 4 个、折线图、条形图、透视表 |

手机竖图嵌报告时限宽居中（约 360px），需求单里注明。

## 第 2 轮：逐图补细节

需求单初稿之后，每张图按页面类型问那一支，再问形态；同一轮把这批图问完，只问需求单里定不下来的，能按行业默认的不问。

| 页面类型 | 定什么 | 问法示例 |
| --- | --- | --- |
| 列表页 | 视图形态 | 物资档案用哪种视图？A 网格表格（推荐） B 按状态分列的看板 C 按日期的日历 D 甘特。筛选、工具栏、列字段按行业默认，不问 |
| 表单 | 展示哪些字段、怎么分组、有没有子表 | 出库单弹窗分几组？A 基本信息 ＋ 出库明细子表 ＋ 审批信息（推荐） B 只放基本信息 C 其他。只有弹窗一种，新建与编辑同一形态 |
| 详情页 | 有没有流程或状态流转、有没有明细子表、页签怎么分 | 出库单详情要不要显示审批进度？A 要，顶部放步骤条（推荐） B 不要。明细、流程、动态怎么放？A 各一个页签（推荐） B 合并成一个页签 C 其他 |
| 工作台 | 这个角色一天要发起什么、要处理什么、参不参与流程 | 库管每天从这页发起什么？A 扫码出库、扫码入库、盘点（推荐） B 只有出入库 C 其他。要处理什么？A 出库审批待办（推荐） B 不参与审批，只看自己的单 |
| 数据看板／大屏 | 结果指标、过程指标、对比维度（问法见下表） | 结果指标 4～6 个，过程指标与对比维度各 3～5 个；筛选范围自己定，不问 |
| 手机端 | 讲几步流程（1 屏用单屏壳，2～3 屏用流程壳）、每屏哪一步、哪屏是企微会话 | 手机图讲几步？A 两步：企微收到待办 → 点开审批（推荐） B 一步，只看审批页 C 三步：企微通知 → 审批 → 出库单已生成。超过 3 步拆两张图 |

数据看板三项指标的问法，选项从材料里的业务数字给：

| 指标 | 问法 | 选项来源 |
| --- | --- | --- |
| 结果指标 | 你核心的结果指标是哪几个？A 出库及时率、库存周转天数、盘点差异率（推荐） B 其他 | 销售额、目标完成率、按时交付率、良品率 |
| 过程指标 | 达成它要经过哪几个环节，各环节看什么数？A 审批时长、拣货时长、复核差错数（推荐） B 其他 | 顺利推进＝转化率类，推进快慢＝时间类，异常分支＝风险类 |
| 对比维度 | 按哪几个维度比？A 按仓库（推荐） B 按业务员 C 按物资类别 D 其他。谁对指标负责就按谁切 | 人员、区域、产品、渠道、批次 |

三项缺一个链路就断：只有结果没有过程，看到问题找不到原因；过程指标必须从结果指标拆出来；缺对比维度，整体持平也看不出哪个团队暴跌。

形态与数据，按条件问：

| 条件 | 定什么 | 问法示例 |
| --- | --- | --- |
| 营销类 | 浮层突出什么（只能是底层没有的内容） | 浮层强调哪个卖点？A 扫码出库后库存实时变化（推荐） B 审批一键通过 C 其他。推荐材料里最强调的那个 |
| 工作台／看板 | 横幅形态、层次 | 横幅要不要背景？A 无背景（推荐） B 纯色 C 背景图卡片。层次？A 白底描边（推荐） B 浅底白卡 |
| 详情页 | 层次 | 层次？A 白底描边（推荐） B 浅底白卡 |
| 任何图 | 数据文案：数字量级、时间范围、脱敏 | 数字按什么规模编？A 月出库几百单（推荐） B 几千单 C 其他。人名？A 常见姓名（推荐） B 材料里的真实姓名 |

用户答完，更新需求单再发一次让用户确认；选了"其他"、回答与材料矛盾、某张图还定不下来，就再问一轮。**没拿到确认不进入步骤 2。** 格式对内对外一致，huoban-solution-report 的调用也是这个格式。

## 问法格式

有选择框工具（如 AskUserQuestion、request_user_input）就用工具，一道提问一道题；没有就用文字版：一轮一条消息，开头"出图前先确认几点："，题目编号，每个选项单独一行写 A、B、C，推荐项放 A 并标（推荐），每题不超过 5 个选项，末项留"其他（请补充）"。选项从材料和行业惯例里给。
