# 2.0.0 需求追问、骨架宏与 HTML 交付

> 2026-09-14

出图流程改成三段：先分轮追问把出图需求弄清、拟需求单确认；再由脚本产出页面外壳，模型只填槽位内容；交付单文件 HTML，整条流程在只有 Python 标准库、没有 Chrome 的沙箱里也能跑完。页面原则按"版式 → 组件 → 色彩"重写，组件名与 huoban-page 官方组件对齐。

## 摘要

1. 新增: references/intake.md——只问决定、事实自己定：第 1 条消息定画布、配色和定不下来的清单维度（主角、讲哪些事；颗粒度随画布定），第 2 条只发需求单初稿让用户增删图，第 3 条起逐图问决定（每轮 3 张图、一题一个编号、推荐带材料理由、依赖题排到下一小轮最前面），终稿"决定与默认"列填实并拿到确认才写骨架；页面类型、端、版式、底色、数据口径由 skill 定，写成默认项进需求单
2. 新增: 页面骨架宏 `<hb-page kind=…>`——外壳、画布高度、浮层定位、栅格由脚本产出，模型不再手写 .stage/.window/.page；`--page kind` 一次给出槽位表、可用宏与最小示例；`<hb-screens>` 手机流程壳 2～3 屏
3. 优化: 组件类名对齐 huoban-page 官方组件 type，登记表 registry.json 成为唯一名录，registry.py 三向校验并校验宏名；全库统一叫"组件"
4. 优化: 页面原则五篇改为"本文用于 → 布局原则（版式表按判断顺序）→ 组件选取 → 色彩"，assets/layout-gallery.html 放各版式线框示意（看板 5、工作台 3、详情页 3）；组件辞典 component-guide.md 按场景列官方组件的适用与举例，选图表类型时才读
5. 优化: 交付物改为 HTML；PNG／SVG 由 export.py 按需导出，找不到 Chrome 只提示不下载；check.py 纯标准库，无 Chrome 时明说"渲染检查未执行"
6. 新增: 槽位校验与规模提示——顶层放错宏、缺必有宏直接报错并给可用清单；单指标个数、表格行数、浮层卡数超出约束给提示
7. 优化: check.py 堵自造组件通道（本图样式里的新类默认 High）、新增未定义 token 检查、报错带候选名；剥掉 CSS 注释后 stage-no-height 与 local-class 才真正生效；`--acceptance` 起草十条验收表
8. 优化: SKILL.md 收成六步流程；references/canvas 三份导出文档合并为 export.md
9. 新增: 按五轮产品实测补齐骨架层——字段组、多项统计、我发起的、表格列表、进度条（两种形态）、分类汇总、面积图、条形图、封面、动态、评论十一个宏；状态条箭头式与选项字段平铺胶囊式两形态；图表卡片与无卡片两种外壳；流程执行记录按实测校正；c3 补六个模板，登记表补宏名与采集状态，registry.py `--coverage` 核对各页面允许的组件都有出处、`--check` 校验宏名与重复条目、`--find` 支持别名
10. 优化: 数据大屏按官方样板重做——不缩放的 24 栅格三列骨架（标题行 → 分隔条 → 左 6｜中 12｜右 6 等高 → 底部折线＋表格），纯 CSS 网格背景、顶部光带、四角角标卡片、斜切标题铭牌；五套主题 cyan／blue／gold／red／light 只改 token；图表系列色五主题固定；大屏中央视觉位加网点阵地图占位，不画国界
11. 新增: 回归集（九张宏片段＋一张手写表单编辑页）放在 skill 同级目录 huoban-image-design-tests/，regress.py 读它并顺带校验 macros.md 与 expand.py 同步
12. 删除: 企业门户、dashboard-data-story.md、visual-components.md（按钮分级并入视觉四原则）、实测记录目录（移到 skill 外）、一次性类名迁移脚本

17. 优化: 组件名一律用登记表官方中文名（标签页、按钮组件、透视表、流程执行记录、大屏指标框等）；浮层只从右侧探出，side=left 报错、手写外壳由 check.py `float-left` 拦；工作台按钮组件 4 个按钮以上独占一行、3 个以下与单指标或待办并排（expand 提示）；表单编辑页只在用户点名时出图；看板追问过程指标 1～3、对比维度 1～2；详情页只在数字与 3 张以上关联记录同时命中时问"字段旁边放什么"；状态色进行中／待办统一为橙；皮肤统一三选一推荐；左栏导览式判据改为常驻筛选 5 个以上；build.py 内嵌本地图片的导入修复；回归集缺失时 regress.py 报错；工作台与看板 `--page` 示例改为层叠式与表格列表明细；去掉 hb-duo 旧名

## 详情

### 1. 新增: 需求追问

| 改前 | 改后 |
| --- | --- |
| 步骤 1 定样式、步骤 2 列需求单四项让用户确认 | 步骤 1 按 intake.md：定盘子 → 需求单初稿 → 逐图决定 → 终稿确认，四种消息各自独立 |
| 需求单要用户给字段和数据 | 不要用户提供真实数据：字段与数据按材料里的行业自己编，只问量级、时间范围、脱敏 |
| 看板要读 data-story 再拆指标 | 逐图决定时先问结果指标，下一轮再问过程指标与对比维度 |
| 页面类型让用户挑 | 由 skill 按场景定页面类型和端，版式不问用户 |

### 2. 新增: 页面骨架宏

expand.py 新增 hb-page / hb-row / hb-float / hb-screens 四个宏和 PAGE_SLOTS 槽位表。槽位顺序来自五篇页面原则的版式表。

| 改前 | 改后 |
| --- | --- |
| 模型写 `.stage{height:624px}`、`.mk-float{top;width}`、`<div class="stage has-float">…` 共 40 余行外壳 | `<hb-page kind="workbench" ws="…" page="…">` 一行，体内按槽位写宏 |
| 浏览器渲染后回填 .stage 高度 | `.stage.auto` 按内容撑高；浮层进栅格（窗口 1440 ＋ 浮层 200） |
| 手机端固定双屏 | hb-screens 2～3 屏，画布宽按屏数 520／1100／1640，屏数或中缝数不对直接报错；hb-duo 保留为别名 |

### 3. 优化: 类名对齐官方组件

按整词替换 520 处，回归图改名前后逐字节一致。横幅是 `rich title`（官方 rich 组件的"大标题"预设），与大幅富文本 `rich hero` 分开；大屏 `screen-*`，手机端 `m-*`，表格页视图 `view-*`。registry.py `--check` 三向核对登记表、结构文件、base.css，并校验每条 macro 在 expand.py 里存在；`--list` 接受中文页面类型。

### 4. 优化: 页面原则与组件辞典

- 五篇页面原则开头一段写"本文用于、用法"，章节顺序 布局原则 → 组件选取规则 → 色彩 → 数据与文案 → 禁止项 → 检查清单。
- 布局章开头是版式表：第一行默认版式，后续行按判断顺序，命中即用；线框示意在 assets/layout-gallery.html，改版式表时同步改。
- 位置与栅格改为"位置 | 规则"表；横幅写法与形态、页签形态、层次、同排等高、图表卡高度抽到 visual-four-principles.md。
- 组件辞典 component-guide.md 按场景分九章，表列 官方名称／适用／举例；页面篇的组件表只管放不放、放几个。
- 页面类型统一叫"数据看板／大屏"；表单篇改名"表单编辑页"，字段选型与布局对齐 huoban-table-blueprint 的原则。
- 实测口径：组件内部原子尺寸照实测，组件的栅格宽高按布局和画面自适应，不硬套。

### 5. 优化: HTML 交付与沙箱

export.py：`--png` 自量画布高度（营销类透明底 1704×(高+96)，产品设计类边到边），`--svg` 用标准库做 foreignObject 封装并校验 XML，`--probe` 供 check.py。check.py 不再在导入时探测和下载 Chrome。

### 6. 新增: 槽位校验与规模提示

| 情况 | 结果 |
| --- | --- |
| 工作台顶层放了 hb-filters | 报错：顶层不能放，可用清单＋"放进 hb-tabcard 或页面末尾" |
| 缺 hb-banner | 报错：工作台必有，给顺序 |
| hb-row spans 加起来不是 24、段数与组件数不等 | 报错 |
| 单指标两组、透视表 >2、横幅两次、浮层卡 >2、一行 >4 组件 | 提示（不阻断） |

### 7. 优化: check.py

规则变化：`local-only-class` Nit → `local-class` High（`--allow-local` 降级）；新增 `unknown-token`、`scale-limit`、`tabs-nested`；`stage-no-height` 只对手写外壳生效；`unknown-component` 附 difflib 候选。

### 8. 新增: 骨架层补齐

| 组件 | 宏 | 说明 |
| --- | --- | --- |
| 字段组 | hb-fields | `# 分组名` 开一组，分组标题行 40 高三色轮转；字段行 69 高；cols 定列数 |
| 多项统计、分类汇总 | hb-multistats、hb-subtotal | 条目 40 高；多项统计右侧数值胶囊，分类汇总右侧纯文本、首行合计 |
| 我发起的 | hb-procs | 行高 80，流程名／单据／当前节点／状态／时间 |
| 表格列表 | hb-list | 外壳标题 40、表头 32、行 35、分页条 40，体内是 hb-grid 语法 |
| 进度条 | hb-progress | style=bar 32 高文字嵌条内；style=text 文字行 24＋细条 4，每条 40 |
| 面积图、条形图 | hb-area、hb-hbar | 与折线、柱状同语法；所有图表宏加 plain 出无卡片外壳 |
| 封面 | hb-cover | 280 高取内容区全宽，页面图标 80 压在下沿，标题 40 号 |
| 动态、评论 | hb-stream、hb-comment | 动态无标题行，单行 40 多行 72；评论有空态与 68 高发布条 |
| 状态条 | hb-steps | 默认箭头式（段 40 高、相邻重叠 10、当前段实色）；pill 出选项字段平铺胶囊 |
| 流程执行记录 | hb-flow | 启动事件行 93、节点 128／89、节点间 2×12 竖线、底部入口 40 |

base.css 新增骨架层组件一节与栅格换算注释（像素高＝20×h−20，列宽＝(容器宽−460)/24，间距 20）；九套皮肤各加 `--tint-cyan`、`--flow-accent`、`--flow-app-bg`。组件的栅格宽高仍按布局自适应，实测 w×h 不硬套。

### 9. 优化: 数据大屏

| 改前 | 改后 |
| --- | --- |
| 星空背景＋地球弧线，示例只有一个大屏指标框 | 官方六张样板的骨架：企业名 3＋大标题 18＋时间 3 → 分隔条 24×2 → 左列指标×2／面积图／饼图、中列视觉位 12×38、右列进度条／对比图 → 底部折线 12×26＋表格列表 12×26 |
| 按 1640/1455 缩放换算 | 不缩放，24 栅格、行高 20h−20、间距 20 与普通页面一致 |
| theme=blue／teal／gold | theme=cyan／blue／gold／red／light，视觉全在 `--screen-*` token |
| 图表配色随皮肤 | 主 #5DA8E9、次 #B6C7D5、饼图六档、进度条四色，五主题固定 |

新增 hb-scol 分栏保证三列等高；hb-svisual map 出网点阵占位。

### 10. 优化: 文档

SKILL.md 步骤：追问并确认需求单 → 写骨架片段（`--page`／`--doc`）→ build → 对照判据 → check 与验收 → 交付 HTML（PNG／SVG 可选）。chrome-env.md、canvas/report-embed.md 并入 canvas/export.md 后删除。
