# 2.0.0 需求追问、骨架宏与 HTML 交付

> 2026-09-16

出图分三段：先分轮问清需求、拿到你确认的需求单；再照需求单画；最后交一个 HTML 文件。整条流程在没有浏览器的服务器上也能跑完。

## 重点

1. **组件名一律用伙伴云里的原名，图上不会再出现系统里没有的东西。** 标签页、按钮组件、透视表、流程执行记录，图上叫什么，你在后台就能照着找到什么。名录集中在一处，画的时候只能从里面挑。

2. **画面外壳自动生成，出图更快也更稳。** 产品壳、页面高度、栅格、浮层位置都由程序算，画图时只管填内容。放错位置、少了必要的组件会当场报错，并告诉你这一页能放哪些组件。

3. **交付一个 HTML 文件，双击就能看，按客户归档。** 不依赖网络和图片，发给客户也能打开。要图片时再另出 2 倍 PNG 或矢量 SVG。一批图放同一个文件夹，文件夹名用客户名或项目名，图名带序号。

4. **出图后自动体检，常见毛病当场拦下。** 自造组件、大片空白、两栏不等高、内容太少、手机组件混进电脑页、浮层遮挡过头，都会被指出来，并告诉你这一栏还能补哪些组件。另外自动起草十条人工验收表，交付前逐条过。

5. **常用组件都补齐了，工作台、详情页、看板要用的都能画。** 字段组、多项统计、我发起的、表格列表、进度条、分类汇总、面积图、条形图、封面、动态、评论，尺寸全部照真实产品实测。矮组件可以在一栏里上下叠放，不会被拉长留白。

6. **每种页面怎么排有了明确判据，同一批图不会张张一个样。** 六类页面各一篇原则，开头就是版式表：满足哪条就用哪种排法。配了一张线框示意图，看板 3 种、大屏 1 种、工作台 3 种、详情页 2 种，一眼能看出每种长什么样。

7. **出图前先把需求问清楚，返工从出图后挪到出图前。** 四条消息依次发：先定画布和配色，再给需求单初稿让你增删图，然后逐图问决定、每轮 3 张图，最后发终稿等你确认。只问要你拍板的事，页面类型、版式、底色、数据这些自己定。需求单固定四列：图名、内容、页面与端、决定与默认。

8. **数据大屏按官方样板重做，左右对称、投屏不变形。** 三列骨架，中间是视觉位，四角有角标；五套主题换色不换结构；地图用网点阵占位，不画国界。

9. **十张基准图守着公共样式，改动不会悄悄带坏老图。** 每次改公共样式或组件写法，都拿这十张重画一遍比对，哪张变了立刻看得见。

10. **营销浮层固定在右下角，不会切在组件中间。** 底图拼好后浮层自动贴到右下，右边探出画布一截，压住底图但不超过四分之一；宽度有上下限，里面的表最多 4 列。

## 其他

- 题里的数量是建议值。你自己给的数量照做，内容多、页面长都没问题。
- 详情页两种排法：默认双栏，主栏放字段和明细、侧栏放数字或流程；信息很少时用单栏。
- 工作台的按钮 4 个以上独占一行，3 个以下和指标或待办并排。表单页只在你点名要时才画。
- 状态色统一红绿灯：完成绿、进行中和待办橙、异常红、未开始浅灰。
- 看板会问核心指标和过程指标，透视表张数不限，多了靠版面排开。
- 皮肤给推荐、备选、品牌色三个选项，报告里已经选过的皮肤直接沿用。
