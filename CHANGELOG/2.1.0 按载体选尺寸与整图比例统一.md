# 2.1.0 按载体选尺寸与整图比例统一

> 2026-09-21

## 重点

1. **字号底线倒推画布宽度，分两档。** 底图主体 8.5px、浮层 7.5px（浮层是「另一屏」的示意，扫一眼看懂即可，比底图小一档反而强化层次）。浮层那档由 `.float-screen` 的 `zoom` 保证：默认尺寸缩 0.8 落在 7.5px，演示尺寸不缩（窗口本就窄，再缩只剩 6.9px）——这也是浮层必须区分两档尺寸的原因，原来这条分档没写理由。

2. **演示尺寸是刚需，不是历史包袱。** 实测演示稿图片位 930–980 宽（1512–1920 视口）：演示尺寸 8.6–9.1px 守住底线，默认尺寸只有 7.4–7.7px 全线击穿。原先 handoff.md 写的「图片位约 1100、演示 10.2px、默认 8.2px」两个数都偏乐观，已按实测改；并补上「演示要在 1512 以上视口放」（1280 视口图片位只剩 791，演示尺寸也只有 7.3px）。

3. **字号底线 8.5px 倒推画布宽度。** 新增「先按载体选画布尺寸」一节：图在载体里的实际字号 ＝ 原生字号 × 显示宽 ÷ 画布宽，底线管主体那一级（表格单元格、字段值 13px），于是 **画布宽 ≤ 显示宽 × 1.53**。建议报告（图显示 1100）用默认尺寸，PPT 图片位（约 1100）用演示尺寸。A4 竖版 PDF 两档都算不过来，文档里写明三条出路。

4. **整图比例从演示尺寸专属改为两档通用。** 规则名 `slide-ratio` → `figure-ratio`、`slide-thin` → `figure-thin`：低于 1.25 报 High，1.25–1.45 报 Medium，目标区间 **1.45–1.85**，高于 1.85 报 `figure-thin`。原来只在 `size="slide"` 时查，默认尺寸完全不查，导致报告配图出现 1.00 这种正方形。

5. **下限让位于信息密度。** 够不到 1.45 时先横向重排（看板图表行 12+6+6、底部两表并排；详情页字段组 cols=4），重排后仍够不到就保留内容，在验收表第 8 条写明理由——不靠缩小字号腾地方，塞不下拆成两张图。

6. **手机图与全屏产品图豁免比例检查。** 手机壳高固定 812，`canvas="product"` 跟着屏幕走，两者都不该被比例卡。

7. **浮层自身宽高比不低于 1.2**（`float-ratio`，Medium）：竖成一条就不像另一屏画面。探针补出 `floatBox`，check.py 按实测判；两块组件改左右并排或把其中一块压矮。

8. **`size` 宏说明同步到新口径。** `expand.py` 的 DOCS 里窗口高还写着 900、比例还写着 1.3–1.6 和旧规则名（900 那处从 2.0.7 起就已过期），`references/macros.md` 作为 `--doc all` 的产物跟着一起错。AI 在步骤 2 读到的正是这份，会照旧数字排内容再被步骤 5 打回。已改 DOCS 并重生成 macros.md。

9. **皮肤库补白云紫蓝。** `assets/skins/baiyun-violet.css` 早已存在但没进 routing.md 的皮肤表，推荐时永远轮不到它；数量口径同步改成「客户定制皮肤 2 套」。

10. **产品设计类豁免改用正则。** 原来写成字符串包含 `"stage auto product"`，与 `build.py` 的 `class="stage[^"]*\bproduct\b` 不一致，类名顺序一变就静默失效。

11. **报告配图落点归口报告 skill。** 本 skill 原写 `figures/{客户或项目名}/`，与 huoban-solution-report 的 `figures/` ＋ `figures/源文件/` 冲突，两边都没被遵守。改成指针，结构由报告 skill 定义。

12. **修好 `export.py --svg`。** base.css 的注释里有裸 `<`（如 `/* 一律 <svg class="ico"> */`），SVG 的 `<style>` 没包 CDATA，XML 解析当成标签开头——**所有图的 `--svg` 都失效**，而它正是没有 Chrome 时的兜底路径（huoban-solution-report 的 embed_figures.py 也这么写）。style 内容现包 `/*<![CDATA[*/…/*]]>*/`。

## 影响

- 默认尺寸的历史图批会新报 `figure-thin`（偏扁、内容少）或 `figure-ratio`（偏竖）——这正是本次要拦的，按提示补内容或横向重排。
- 旧常量名 `SLIDE_RATIO_OK / _HIGH / _THIN` 在 check.py 里保留为别名，外部引用不破。
